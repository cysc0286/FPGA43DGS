三、证据 B：现行数值门禁需要修改

B1. 现行门禁是什么

verify.py 对每个子图做逐元素比对：

np.allclose(actual, expected, rtol=2e-3, atol=2e-4)

任一分区不过，立即抛异常并终止，后续步骤（包括生成高斯、渲染、图像评估）都不会执行。

B2. 证据一：七个子图全部独立上 NPU，画质全部合格

子图门禁结果（max_abs）最差 NPU-vs-CPU 画质判定
to_disparity0.027344.01 dB合格

门禁判 7 个全败；画质看 7 个全过。两套判据给出完全相反的结论。

B3. 证据二（最关键）：数值排序和画质排序是反的

子图max_abs数值排名画质画质排名
depth_head0.2298最差（第 7）67.01 dB最好（第 1）
to_disparity0.0273第 344.01 dB最差（第 7）

to_disparity 的逐元素误差只有 depth_head 的 1/8.4， 但它的画面影响差了 23 dB。

这不是“阈值定得偏严”，而是“测的东西不对”。
max_abs 测的是子图出口每个数字差多少；画质取决于这个误差在网络里往哪儿流、被谁放大。 to_disparity 输出视差，直接决定高斯的深度排序和位置，0.03 的误差落到图像上就是像素级错位； 而 depth_head 的特征后面还要经过多层抽象，误差被摊平了。
一个测局部的指标，无法预测全局的结果。

B4. 证据三：门禁让“更重要的评估”永远跑不起来

verify.py 的执行顺序是：

for name in partitions:
    if not passed: raise        # ← 7 个子图全在这里中断
attach_partitions(worker)       # ← 永远到不了
infer(...)                      # ← 生成高斯
check_images(...)               # ← 渲染、PSNR/SSIM（从未执行过）

结果是：一次完整上板，只换来 7 行“失败”，高斯数据、渲染图像、PSNR 一个都没有留下。 而这三样才是判断“能不能用”的依据。

B5. 证据四：2e-4 这个阈值，在 10 位精度上本来就到不了

  • ZG330 走的是 10 位尾数运算（TF32 / FP16 同属 10 位尾数），单次舍入相对误差约 5×10⁻⁴；
  • backbone 有 16 层卷积，误差逐层累积，实测中位相对误差 0.65%；
  • 门禁的绝对阈值是 2×10⁻⁴，比单次舍入误差还小；
  • 实测越界比例：分区级 77.66%，即使放宽到高斯级（5e-3/1e-3）仍有 44.81%。

在 10 位精度上要求 2e-4 的绝对一致，等于要求硬件做到它做不到的事。

B6. 建议的修改方式

层级判据用途
L1 逐元素
（保留）		 现有 rtol=2e-3, atol=2e-4 仅作诊断：定位“哪个子图、哪个通道有问题”。 不再作为放行条件，不通过也继续执行后续步骤并保留数据。
L2 图像级
（新增为验收）		 留出视角上 NPU vs CPU ≥ 40 dB， 且 NPU vs 真值 相对 CPU 的 PSNR 下降 ≤ 0.5 dB 作为放行条件：直接对应“画面能不能用”，也是下游渲染真正关心的东西。
为什么这个改动不是“放水”：它没有降低任何标准，只是把衡量对象从“中间张量的每个数字” 换成了“最终画面的质量”。前者已被实测证明与后者无对应关系（B3），后者才是项目目标（PSNR / 可视效果）。 同时 L1 完整保留，出现真实 bug（如权重错位）时它依然会报警——那种情况下的越界是 100% 或局部集中， 与本次的均匀分布（八组均为 76%~78%）在形态上就能区分。

四、关于“绕过门禁”的说明

先给结论：NPU 是真实执行的，不是模拟、也不是回退到 CPU。 被跳过的只有“数值门禁这一关的判决”，而 NPU 上的计算本身一行没改。

为免误解，把两件事分开列：

问题答案依据
NPU 有没有真正执行？ 有，真实执行 设备初始化成功（A1）、npu_executed: true（A2）、 NPU 单次 23 ms vs CPU 约 1.35 s 的 57 倍差异（A3）、 输出的高斯渲染后与 CPU 差 64 dB（A4）。
数值门禁的判决有没有被跳过？ 跳过了 诊断脚本去掉了两处 raise，让流程能继续走到“写高斯、渲染、算 PSNR”。 目的正是产出本报告第二节的数据，用来论证门禁本身需要修改。

也就是说：被执行的是 NPU 计算，被跳过的是“通过/不通过”这一判断。
而正是因为跳过了判断、拿到了图像数据，才证明了那个判断本身测错了对象。
