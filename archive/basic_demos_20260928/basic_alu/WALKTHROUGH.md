# 运算器源码与时序导读

主工程：`platform/basic_alu_fpga/fpai_demo_vivado.xpr`。

源码入口：[basic_alu.v](rtl/basic_alu.v)。Vivado 使用的是 `platform/basic_alu_fpga/rtl/adder_op/basic_alu.v` 副本，本次核验与该源码逐字节一致。修改源码后需要同步到工程副本、重新验证和构建；本导读没有修改运算逻辑。

## 先看 4 个位置

1. **第 15 行：状态定义**。`IDLE=0` 等待请求，`SIMPLE=1` 执行普通运算，`MULTIPLY=2` 执行迭代乘法，`SIGN_RESULT=3` 修正乘积符号。
2. **第 45 行：接收请求**。仅当请求序号不同于已完成序号时接受；保存 A、B、操作码和序号。输入随后变化不会改变本次已接受的计算。
3. **第 60 行：普通运算**。`case(operation)` 选择加减、逻辑、移位或比较结果，在下一上升沿更新 `result` 和 `completed_seq`，同时返回空闲。
4. **第 79 行：乘法循环**。每拍检查乘数最低位，若为 1 则累加当前被乘数；被乘数左移，乘数右移。32 拍覆盖乘数的所有位。第 92 行在需要时将无符号幅值乘积取补码。

`status[0]` 表示忙，`status[1]` 表示非法操作。序号相等表示命令已经完成，不会自动重复执行。

连接入口是工程副本 `adder_top.v` 第 74 行的 `U_basic_alu` 实例，CPU 通过寄存器写操作数和请求序号，再读结果；完整地址见 README 的 ABI 表。

## 功能时序：从接受请求的 E0 上升沿计时

时钟为 100 MHz，每周期 10 ns。E0 完成输入锁存和状态切换，以下拍数指 **E0 到结果/完成序号更新之间的间隔**，不包括 CPU 写寄存器、接口传递或软件轮询耗时。

| 运算路径 | E0 | 后续时钟沿 | 接受到完成 |
|---|---|---|---|
| 普通运算 | 锁存输入，进入 SIMPLE | E1 写结果，完成序号更新 | 1 周期，10 ns |
| 无符号乘法/不需要符号修正的有符号乘法 | 初始化累加器、乘数、被乘数 | E1～E32 移位累加，E32 完成 | 32 周期，320 ns |
| 需要符号修正的有符号乘法 | 取输入幅值，记录符号异或 | E1～E32 移位累加，E33 取补码并完成 | 33 周期，330 ns |

符号修正由两个输入符号位的异或决定，因此包含负数与零相乘、最终结果为零的情况。上述时间是当前 RTL 在指定时钟下的核心周期延迟，不是测得的端到端性能，也不表示每拍可以接收一条命令。

## 查看真实仿真波形

仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\examples\basic_alu\open_waveform.ps1
```

脚本编译一个 5 组输入的短测试，核验结果和精确周期数，保存 WDB/WCFG 后打开 XSim 窗口。关注这些信号：

- `opcode / operand_a / operand_b`：运算选择和输入。
- `request_seq / completed_seq`：命令提交与完成。
- `status / result`：忙标志、错误标志、输出。
- `dut/state / iteration / accumulator / multiplicand / multiplier`：状态机和乘法迭代过程。

依次显示：17+5、17−5、7×9、(−7)×9、(−16) 算术右移 2 位。十六进制结果依次为 `16`、`0c`、`3f`、`ffffffffffffffc1`、`00000000fffffffc`。第四项是完整 64 位补码；第五项仅在低 32 位保存补码。

## 静态时序：布线后的路径检查

已打开的 routed checkpoint 窗口中有以下命名报告：

| 报告 | 用途 | 本次检查 |
|---|---|---|
| `ALU_Setup_100MHz` | 经过 ALU 的建立时间路径 | 最差裕量 +4.560 ns |
| `ALU_Hold_100MHz` | 到 ALU 寄存器的保持时间路径 | 最差裕量 +0.085 ns |
| `Board_Setup_Violations` | 整板建立时间失败路径 | 原视频通路 2 条，−0.090 / −0.068 ns |
| `Board_Timing_Summary` | 整板检查汇总 | 未通过；另有周期/脉宽违例 |

第一条 ALU 建立时间路径从 `b_reg[4]` 到 `result_reg[9]`，数据路径延迟 5.310 ns，经过 6 级逻辑。它对应移位选择逻辑；最差路径不是由乘法迭代的总拍数直接决定的。报告还计入时钟到达、偏斜、不确定度和寄存器时序要求，因此不能用 `10−5.310` 直接替代报告中的 Slack。

双击报告中的路径可以查看起点、终点及逐级延迟。**功能仿真波形与静态时序报告回答的是不同问题**：前者检查每拍的逻辑值和协议行为，后者检查实际布线后的路径是否满足时钟约束。整板仍未通过时序验收，不能从 ALU 的正裕量推断视频或 NPU 全部可靠。

本轮仅打开工程/检查点、读取报告并新增演示测试，没有重新综合、修改约束、下载位流或重启板卡。
