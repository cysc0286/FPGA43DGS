# NPU 加速机会：以质量合格后的总耗时为目标

日期：2026-09-28。用户最新要求：优先加速，画质达到合格门槛即可，不把低资源利用率作为优化目标，允许充分使用已有 CPU、NPU、FPGA。本文是基于当前代码、历史实测和作者公开代码的分析，没有修改算法、训练预算、位流或默认后端，也没有新增板端速度结果。

## 哪个环节有最大收益空间

综合判断：若允许在质量门槛内改变算法，最大机会是把 B 组逐场景迭代优化的一部分或全部换成预训练网络的前馈高斯预测，让 NPU 执行规则、密集的网络计算，FPGA 继续渲染。只加速描述子点积不足以支撑“大幅加速整链”的主张。

这是一项待测的架构判断，不是已证明的 ZG330 加速结果。不能把 GPU 论文速度或网络峰值算力搬到当前板卡上。

| 候选 | 可能受益的原因 | 主要风险/边界 | 建议定位 |
|---|---|---|---|
| 学习式特征提取，例如 XFeat | 图像卷积有规则张量与权重复用；覆盖特征提取而非只算相似度 | 与 SIFT 是算法变化；完整网络算子映射、后处理和几何质量须验收；其 CPU 实现本身也高效 | 最近的可独立部署候选 |
| 匹配矩阵及设备侧 Top-2 | 批量点积可用 NPU；设备内归约避免回传完整分数矩阵 | Top-2 的实际芯片映射未验证；近似分数可能改变对应关系 | 与特征提取一起优化，不能只看 MatMul |
| 有位姿的前馈高斯预测，例如 MVSplat | 用一次网络推理替代大量逐场景更新，主干/正则化含卷积和注意力 | 仍需要位姿；cost volume、grid_sample、输出适配和多窗口融合可能变成热点 | 最大收益主候选，保持现有 PoseSet 边界 |
| 无位姿前馈预测，例如 NoPoSplat | 对稀疏未给位姿图像预测统一坐标中的高斯，有机会一起缩短位姿与场景拟合 | 少量视图不等于完整视频全局建图；模型移植、相机约定与窗口对齐均未实现 | 更激进的后续候选，需新接口版本 |
| 大批高斯投影/协方差/SH | 已有后端 CPU 属性阶段耗时显著，可研究融合/常驻批计算 | 算术强度和输出量限制；模型读取/排序不会因投影上 NPU 自动消失 | 渲染优化候选，先获得纯计算剖析 |
| 稀疏 BA、动态增密、深度排序、逐像素有序合成 | 当前数据结构或顺序依赖与现有密集 NPU 图不匹配 | 改写成本和跨设备数据组织可能大于算术收益 | 暂留 CPU 或已有 FPGA；不是当前首选 NPU 工作量 |

XFeat 作者输出 64 维描述子，当前 SIFT 候选按 128 维整数描述子设计，不能只换一个模型文件继续沿用旧匹配规则。应在 A 内同时适配特征、匹配及 COLMAP 接入，A→B 的 PoseSet 接口保持不变；与同一个 XFeat CPU 实现对比后，才能区分算法替换和 NPU 本身的收益。

## 当前实测告诉了什么

### ARM 位姿前端

历史 `arm_sfm_v1`，30 帧，30/30 注册，1076 点，重投影 0.434797 px。以下为同一次运行，不含高斯训练和最终渲染：

| 部分 | 秒 |
|---|---:|
| 特征提取 | 52.038 |
| 匹配 | 22.980 |
| 增量几何建图/求解 | 56.349 |
| 其余准备、去畸变、适配等差额 | 26.442 |
| 整个 SfM 命令 | 157.809 |

前两项占 47.54%。假设其余完全不变，前两项耗时趋近零时整个 SfM 上限为 1.906 倍；二者都加速 10 倍时整个 SfM 约 1.748 倍。这是算术上限，不是 NPU 测量。不同算法导致匹配数量/求解迭代变化时，不能照搬该上限。

电脑上一轮四阶段命令合计 39.188 秒，高斯模块 28.523 秒，占 72.78%；这只说明该电脑样本中优化阶段占主导，不能当作 ARM 耗时占比。ARM 完整训练尚未验收，当前不能给整个板端视频→图像链预测一个可信的加速倍数。

### NPU 匹配负结果

历史第一对 CPU 225.514 ms，NPU 常驻加 CPU 精确重算 668.218 ms。CPU 点积约 52 ms；NPU forward 约 20.9 ms，但 SFB 回读/转换约 44.3 ms、写入约 3.3 ms，另有精确重算约 126 ms及候选筛选等。三对 NPU/CPU 耗时比为 2.963/2.908/3.003。

这表明核内更快没有形成整段更快。新速度优先目标允许设立“近似分数、按几何和最终图像验收”的新候选，无须沿用旧整数参考逐项一致要求；旧精确结果必须保留。原始误差曾改变匹配数量，因此也不能直接删掉纠错后宣布质量合格。

说明数据布局机会的算例：两图各 2048 个描述子，FP32 全相似度矩阵 16 MiB；若设备已完成双向全局 Top-2，每项返回 FP32 分数和 int32 索引，只需约 64 KiB，即逻辑输出量约缩小 256 倍。这不是当前 DMA 实测或已实现 Top-2；应将 Top-2 放在 NPU/FPGA 或与设备执行融合的路径内，在 CPU 上拿到全矩阵之后裁剪不能节省已有回读。

### NPU 几何精度代价

旧 `npu_3dgs/VALIDATION.md` 记录用基数拆分满足严格误差标准，输出从每高斯 5 个数扩大到 405 个，增加 81 倍。直接 TF32/FP16 曾有投影误差，不能追认原版本合格；但新画质门槛下应重新评估归一化坐标、混合精度和批融合，而非默认保留高昂纠错。NaN、错误索引、错误坐标系和缓冲覆盖仍属功能错误。

## MVSplat 为什么是重点候选，如何接现有后端

作者实现接受图像、内外参和深度范围，经特征提取、多视图相关/深度推断与属性头输出高斯。项目提供预训练权重；网络权重预先训练后固定，每个场景变化的是输入及输出高斯参数。部署时不要求为每个房间重训通用网络，但分布外画质和视频全局一致性必须验证。

建议保持 A 的 PoseSet；在 B 内建立独立的前馈候选，输出经过适配的 RenderInput；C 的冻结 FLICKER 渲染器继续复用。默认 CPU/OpenSplat 链保留为质量与速度对照，不因这份分析切换主线。

需要做的部署工作是完整子图而不是一个 MatMul：固定输入形状、主干与后续网络尽量常驻 NPU；核对卷积/注意力/归一化/softmax/grid_sample 映射和回退；将不支持且耗时的采样/归约融合，必要时才研究 FPGA 实现。所有 CPU 回退、张量格式转换、设备启动和结果搬运计入候选耗时。

源代码确实有一次双线性采样生成 `[B,C,D,H,W]`，再沿 C 做相关归约。按作者 re10k 配置两视图、256×256、下采样4、C=128、D=128，若 FP32 完整物化，该中间量为 512 MiB，归约结果约 4 MiB。这里的重点是融合采样和归约以减少大中间量访存；不是因为内存占用高就排除算法。这是张量尺寸估算，不是实测峰值或当前硬件可用容量声明。

输出接口也要适配：作者配置 SH4，当前冻结后端固定 SH3；可以评估截阶，但须量化质量变化。opacity/scale 的物理值与 PLY 的 logit/log 存储不同；旋转需统一世界坐标。作者适配器返回世界协方差和旋转后的 SH，而用于可视化的原始 rotation 有相机坐标语义，不能直接把四元数写入冻结 PLY。两个256×256视图、每像素一个高斯可产生131072个高斯，可能增加后端排序与渲染工作；必须连同模型合并/筛选一起测总时延。

NoPoSplat 公开实现直接从未给位姿的稀疏图像预测规范坐标中的高斯，提供 2/3 视图权重，是进一步绕过部分 SfM 的参考。不能把独立图像对的输出直接拼成同一个房间地图；长视频的窗口对齐、尺度和重复高斯处理需另建机制。其 GPU 依赖不是本板性能证据，算子图移植尚未开始。

## 速度优先的评估方式

1. 排名指标为视频输入到第一张合格目标视角图像的总时间，并单列同一场景后续渲染时延。逐场景训练一次与每帧都运行重建必须分开记账。
2. 分开比较“同一模型/算法 ARM 与 NPU”的硬件收益，及“原 CPU SfM+优化与前馈链”的算法系统收益。不能把少做迭代全部归因于 NPU。
3. 预先固定留出视角、PSNR/SSIM 与明显结构错误门槛；可把相对当前参考下降不超过 2dB/0.03 作为待确认的初筛建议，不当作用户已批准的绝对合格线。新视角没有 GT 时不能伪造分数。
4. 资源占用用于解释容量、调度及 DDR 竞争，不作为“越低越好”的排名指标。允许 CPU 多核、NPU 常驻、FPGA 并行充分工作；若算法会 OOM 或回退导致变慢，仍需改实现。
5. 保留三个对照：当前 CPU 重建＋CPU/FPGA渲染；同一前馈模型 CPU 参考＋冻结渲染；前馈模型 NPU/CPU混合＋冻结渲染。全链最后一种在本板实跑后才可宣布 NPU 加速。
