# NPU 匹配的两轮实板调试

日期：2026-09-28。真实设备：30TAI Lite、ARM Cortex-A53、ZG330、ICraft 3.36.1。CPU 为板端 NumPy 1.23.0，OMP/OpenBLAS 线程设为 2。输入沿用 v1 三对 SIFT 描述子，不换样本挑结果。原冻结 FPGA 渲染包和 BOOT 未修改。

## 验收结果与失败版本

1. 原目录假设 `sdk/include` 不适合板端实际 `sdk/usr/include`；`sdk_paths()` 现在同时检查两种布局和必需库。Linux 使用 `gnu++17`，解决 SDK 公共头文件的空可变参数宏问题。
2. `Session.apply()` 将 12 个 HardOp 合并为一个，顶层名称为空；递归检查 `sub_hard_ops` 后确认 Matmul 48 实际绑定 ZG330，而不是只凭搬运算子判断。原错误和修正版本均保留。
3. 原 128 块 TF32 全分数最大误差 0.00197983，原 0.0002 门槛失败，直接匹配 685 个而整数参考为 682 个。FP32 备选产生含 NaN 的输出，也未获准替换原候选。
4. 新增“近似点积 + 少量 CPU 精确重算”的独立候选。每块保留距行/列第二名不超过两倍误差预算的候选，再以整数点积求精确分数。保证是有条件的：必须满足所有原始误差均不超过预算；当前 0.003 仅由本次输入逐分数审计确认。不能修改 v1 门槛后宣称原方案通过。
5. 常驻 C ABI 最初直接 `Tensor.read()` 产生约 0.997 的错误；恢复 SDK 的 SFB 数值/布局转换后通过。当前仍有转换和复制，不能称零拷贝。
6. 当前三对共 2,194 个匹配逐项等于 CPU 整数参考，全部 3 次重复一致。写入独立 COLMAP 数据库后分别得到 672/713/767 个内点，共 2,152 个；原数据库哈希不变。这是三对局部接入验证，未运行 NPU 全视频 SfM 或 NPU 高斯训练。

第一对的典型分解：CPU 打包 27–28 ms、矩阵乘法 51–53 ms、合并筛选 143–146 ms。NPU 常驻总约 668 ms，其中 SDK 写入约 3.3 ms、forward 20.9 ms、SFB 回读/转换 44.3 ms；候选精确点积约 126 ms，另有候选选择、数组转换和合并开销。forward 本身较快，但整个设备调用约 68 ms 已超过 CPU 矩阵部分约 52 ms，额外选择/重算进一步抵消收益。因此下一步若研究此候选，应先把选择与重算融合成原生实现并减少输出转换，而不是仅增加 NPU 调用数。

## 正确性、资源和适用边界

三个 256 块原始最大误差分别为 0.00165176、0.00183487、0.00167084；原 v1 门槛均失败。CPU 重算后最终索引完全一致，不代表原始全分数精确。运行进程峰值 RSS 48,664 KiB（约 47.52 MiB）；这是 Linux `ru_maxrss`，不包含内核或 NPU 私有内存，且涵盖检查与计时整个进程。

前两对每对逻辑输入和逻辑输出各 6,553,600 字节，最后一对各 9,437,184 字节；这是缓冲协议数据量，不是测得的物理 DMA/总线字节。硬件算子运行位置经过绑定核对；实际 NPU利用率、带宽利用率、完整 CPU 占用时间序列和功耗未测。未新增 FPGA RTL、LUT/FF/DSP/BRAM 或时序结果。

Windows 11 项回归通过，含实际 C++ CPU 文件 ABI、尾块/重复/损坏数据、两种 SDK 布局和带误差候选筛选。证据 `npu_regression.log`。硬件上默认保持 CPU 前端：当前候选的价值是闭合部署和误差验证，而非获得加速。

## 复跑入口

在板端独立目录，设置 SDK 动态库路径并保持与已验收版本相同：

```bash
export LD_LIBRARY_PATH=/root/heterogs_npu/sdk_3.36.1/usr/lib/aarch64-linux-gnu
export OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2
python3 build_runner.py --kind npu --shared --sdk /root/heterogs_npu/sdk_3.36.1 --output new_native_build
python3 benchmark_resident.py --cases cases --library new_native_build/libhgs_matcher.so --model compiled256/sift_pair_dot_ZG.json --raw compiled256/sift_pair_dot_ZG.raw --output new_run --tile 256 --repeats 3 --bound .003
```

程序拒绝覆盖旧证据目录。更换输入后仍需原始分数预算检查和最终索引检查；不得因为旧输入过关而绕过。模型/参数/库的 SHA 与运行记录共同确认具体版本。
