## 实机发现与修正

1. 请求 720p 30 fps 时驱动会自动改成 60 fps；正式采集显式使用实际档位 60。
2. 旧 FFmpeg 写 AVI 会把 2 秒、115 个实际 JPEG 包声明为 242 帧/120 fps，
   直接按容器帧数选帧会读到不存在的帧。改为 MJPEG stream-copy 到 MKV；
   标定/自动选帧按 ffprobe 实际 JPEG 包序号计数。未重新编码图像。
3. 板卡文件系统开始仅余 373 MiB。把原“需要整段未压缩大小”的预检改为压缩文件硬上限
   `-fs ≤256 MiB`、预留 64 MiB、检查最终时长/帧率。没有删除板卡旧实验或调整分区。
4. 新增 `video_input/preview.py`：FFmpeg 原始 JPEG → 有界解析缓冲 → 最新完整 JPEG → HTTP 预览。
   不依赖模型、标定、OpenCV 或 FPGA；浏览器约每 250 ms 更新一次，原始采集仍约 60 fps。
   过期超过 3 秒、断流或超大 JPEG 返回错误，不把旧图伪装成实时帧。
5. 板端 Torch/OpenCV 有 static TLS 导入约束；解码验证沿用原环境的 libgomp 预加载。
   预览使用系统 Python 3.8，无需加载该模型环境。
