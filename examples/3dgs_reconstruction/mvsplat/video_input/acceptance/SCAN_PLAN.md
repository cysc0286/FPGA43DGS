# 当前四步共用的扫描与采集方案

## 统一参数

阶段02、03共用`video_input/camera_scan_bow.json`，不另外保存重复轨迹。水平−30°至+30°，俯仰依次+30°、0°、−30°，两轴标称20°/s。上层向右、中层向左、下层向右，只在两端换层，最终回中。833个指令点、20 ms间隔，最大脉宽步长5 µs，原10 µs保护及俯仰±45°限位不变。

完整扫描计划16.66秒，包含到起点、换层、端点稳定和回中。阶段03先确认录像出帧，再保留0.5秒、执行扫描、保留0.5秒后停止，计划录像17.66秒。加2秒调用余量，预检预算19.66秒；20秒为保护上限，不是固定录像长度。真实SDK调用、Linux调度和机械跟随尚待测量，不能把上述时间写成实测。

上一轮30°/s方案在`camera_scan_bow_fast15.json`，原46.06秒慢版在`camera_scan_bow_conservative.json`，均须显式选择。修改轨迹不需要重新综合FPGA。

## 60帧假设与现场选择

在稳定60fps假设下，每帧标称转角0.333°，每层水平扫描3秒、约180帧，三段水平扫描约540帧；完整录像约1060帧。这些是原始候选画面，不是MVSplat前向次数，也不是全部被用于重建的帧数。

采集默认仍为已知的1280×720、30fps。现场先运行`python3 -m video_input.capture --device /dev/video0 --probe`；确认支持同分辨率60fps后，再给阶段03加`--fps 60`。程序仍验证实际帧率、时间戳和文件完整性，不把请求60fps当作真实60fps。阶段04从原始采集凭据读取模式，不单独重设帧率。

曝光与帧率分开核验。按已有相机标定在画面中心一阶估算，20°/s、1/120秒曝光约移动3.2个原始像素，1/240秒约1.6个；照明允许时可据此试验，尚未自动设置曝光。记录拖影、端点振动、换层跟随及USB掉帧情况。

## 覆盖预期与验收范围

沿用HF868的1280×720标定和历史重建裁剪方式，原始画面的针孔视场约60.4°×36.3°，当前正方形重建输入约31.3°×31.2°。三层连续扫描的中央水平截面约−45.6°至+45.6°，正前方竖直截面约−45.6°至+45.6°。这是前方约90°宽、90°高的不规则扇区；斜角处轮廓会变化，不是完整矩形或360°整圈。

理想连续三层视锥的球面并集约2.34 sr、约整球18.7%，只是几何方向估算。实际有限选帧、遮挡、纹理、曝光和高斯质量均会使可用覆盖缩小，不将此值标作实测覆盖率。

上层中央约+14.4°至+45.6°，中层约−15.6°至+15.6°，下层约−45.6°至−14.4°；相邻层中央重叠只有约1.24°。阶段04必须分别观察三层及两处交界。现有自动选组重点是水平方位，三层数据是否充分利用、跨层接缝是否合格仍待现场确认；本次同步没有新增分层选帧或融合算法。

## 四步各自回报什么

1. **电机**：J17水平23、俯仰21、共地2，周期、电平、方向、回中及小角度动作。寄存器值不替代机械测量。
2. **轨迹**：三层顺序、端点换层、实际角度与运动时间。确认本步生成的计划配置与阶段03一致。
3. **同步录像**：先录后动、全程完整、实际帧率与录像长度、15–20秒目标、拖影与振动。保存原视频、原始凭据、轨迹和交接文件。
4. **重建渲染**：沿用原素材和匹配标定，先单组再多组，经NPU与FPGA得到实际首帧，并通过网页检查上／中／下层各方向及交界。录像时间、场景准备时间、换视角渲染时间分别报告。

以上仍按四个独立入口验收，不把跨步骤手动等待计入自动闭环成绩。测试命令见[README.md](README.md)，现场逐项填写[CHECKLIST.md](CHECKLIST.md)。阶段02的默认预览命令会在指定的工程外目录生成833点轨迹CSV及参数摘要，无需下载压缩包或预存测试视频。
