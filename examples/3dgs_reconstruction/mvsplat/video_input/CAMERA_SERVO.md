## 本次机械限位

以用户确认的水平中位 1500 µs 为零点，俯仰软件仅接受 1000–2000 µs，RTL 同样独立限幅到此范围，按厂商标称映射对应 ±45°。ABI 升级为 2；控制器连接时须读回硬件限幅，旧 ABI 或配置不符则不写寄存器。角度对应关系仍是标称值，机械实际角度和回差尚未实测。

首次仅单轴执行 1500→1450→1500→1550→1500 µs，标称约 ±4.5°，每 20 ms 最多变化 2 µs，结束后关闭脉冲。此命令计划已仿真和软件验证，不能据此声称实物已运动。

## 本机复现

在 mvsplat 目录运行：

```text
python -m unittest video_input.test_camera_servo -v
python -m video_input.camera_servo --axis pan
python -m video_input.camera_servo --axis tilt
```

后两条只打印计划，当前即可运行。实物运行参数 `--execute --uio /dev/uioN` 仅能在新固件已集成且 UIO 映射经过核实后使用；`N` 不能照抄或猜测。硬件 ID 不匹配时不写寄存器。

### 当前板卡的 SDK 原生入口

当前 Linux 没有 UIO 映射，因此实际候选采用 `camera_servo_native.cpp`，经现有 ICraft 3.36.1 的设备寄存器接口访问，无需猜测 Linux GPIO 编号。板端编译脚本为 `build_camera_servo_native.sh`；候选部署目录是 `/root/camera_servo_20261115`。

```sh
sh build_camera_servo_native.sh
./camera_servo_native dry-run
./camera_servo_native status
```

默认和 `dry-run` 都不打开设备；`status` 只读。控制程序会核对 SRV1 身份、ABI 2、100 MHz 时钟参数、50 Hz 周期、500 ms 看门狗及两轴限幅，任一不符即拒绝写入。板端当前旧固件的身份检查失败属于预期负对照，并不表示运动功能已验收。

仅在新固件通过审查且断电完成 23/21 换线、现场确认机械无干涉后，按单轴顺序运行：

```sh
./camera_servo_native smoke pan --execute --wiring-j17-23-21
./camera_servo_native smoke tilt --execute --wiring-j17-23-21
```

两条不可并发执行。每条都从 1500 µs 起步，只做标称 ±4.5° 小幅往返，回中后关闭 PWM；这不是全行程测试。进程正常退出或收到 SIGINT/SIGTERM 时尝试关闭脉冲，进程失联由硬件心跳超时停脉冲兜底。停脉冲不等于切断舵机电源。

仿真：依次使用 Vivado 2018.3 的 xvlog 编译 RTL/testbench，xelab 生成 `camera_servo_sim`，xsim `camera_servo_sim -runall`；输出目录与源码分开。原始证据在项目 outputs/camera_servo_20261115。

## 收益及待验项

硬件计数器直接产生 20 ms 周期和整微秒脉宽，软件每次只发少量寄存器指令；无需持续在 ARM 上翻转 GPIO。代价是需要修改 PL 顶层和寄存器路由，重新实施布局布线。整板候选综合与布局布线资源见上节；现有 CPU/NPU/FPGA 渲染时延、画质本轮未做实板复测，电机定位精度、实际电流和功耗均未测。模块参考综合也不能代替整板时序与板端输出测量。
