# 2026-11-01 板端历史记录清理按钮

用户明确允许删除板端旧摄像头记录，不要求板端归档，只保留最近结果。
本轮实现并部署存储按钮，未实施上一轮待批准的流式重建方案，未修改权重、几何算法或 FPGA 固件。
main 基线仍为 a6d621767b5b91c9142954837ee5a04197e8995f 加本地未提交增量；未提交、推送。

## 页面行为与删除边界

刷新 http://127.0.0.1:18433/ 后，在“板端存储”卡片点击“清理历史记录（保留最新）”。
按钮返回删除项数、释放的逻辑文件大小和文件系统当前可用空间；可重复点击，第二次无历史时返回 0 项。
不会自动归档，也不会在每次录制完成后自动删除。

清理仅限当前候选的 `/root/fpga43dgs_reconstruction/camera_buttons_20261101/sessions`：

- 仅处理符合当前 clip_/scene_ 完整命名格式、具有对应生成元数据的会话目录，以及被删除场景的同名 `.log`、`.measurement.json`。
- 保留当前短片、最近完整短片、最近完成且首帧哈希仍通过的成功场景及其来源短片。
  新片尚未重建时，可能暂时保留两段短片，以便上一场景继续可用。
- 额外保留生命周期协调器正在引用的场景及来源路径。录制启动、录制、保存、重建期间服务端拒绝清理，界面同步禁用按钮。
- 当前目录以外的实验、权重、模型代码、工具、系统、BOOT 都不属于删除范围。
  无元数据的未知目录、符号链接和含链接的会话不递归处理；Windows junction 同样拒绝。
- 使用原生 pathlib 文件操作，删除前及递归过程中校验真实路径在指定存储目录内，不拼接 shell 删除命令。
  API 不接受调用方传入删除路径，POST 必须带当前页面的 session token；互斥锁防止与录制、重建请求交叉。

实现归属为 `video_input/recording.py`；`initialize/camera_ui.py` 只协调运行路径、恢复与子进程。
`rendering/viewer.py` 增加已保存场景入口，验证 PLY、Gaussian NPZ、上下文 NPZ 及对应记录哈希后加载。
恢复时先检查场景 VIDEO_COMPLETE 来源与当前短片一致，保持旧事件、日志和失败记录原样。
