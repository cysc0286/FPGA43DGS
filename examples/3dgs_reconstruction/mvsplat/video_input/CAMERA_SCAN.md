# ARM 正式扫描程序

当前俯仰复验出现突然大幅后仰，舵机外供已关闭。零位尚未验收，暂停执行扫描；最新故障与 ABI3 完整脉冲停止候选见 [MOTOR_INCIDENT_20261116.md](MOTOR_INCIDENT_20261116.md)。以下默认角度和脉宽仅为原计划，不能直接作为已校准实物参数。

本程序属于 `video_input` 的采集运动控制。ARM 规划并提交两轴位置，已有双路 FPGA PWM 持续产生脉冲；修改扫描参数不需要重新综合。最新实板记录见 [CAMERA_SERVO.md](CAMERA_SERVO.md)：候选固件已上板，两轴能运动，但俯仰 1500 µs 实际朝下约 30°，默认扫描固定中位尚不能作为镜头水平零位。先用单轴 `jog` 完成安装姿态校准，再调整扫描配置；本文的标称轨迹不是实物覆盖验收。

## 文件与分工

- `camera_scan_bow.json`：当前默认的三层弓字扫描，俯仰 +30°、0°、-30°，仅在水平两端切换俯仰。
- `camera_scan_bow_conservative.json`：原46.06秒慢速三层方案，作为机械跟随或画质不佳时的回退。
- `camera_scan_bow_fast15.json`：保留上一轮30°/s快版，完整扫描11.66秒、计划录像12.66秒，须显式选择。
- `camera_scan_profile.json`：保留原单层逐点扇扫配置，便于对照和回退；须通过 `--profile` 显式选择。
- `camera_scan_spiral.json`：水平与俯仰同步变化的局部螺旋段配置，作为独立可选示例。
- `camera_scan.py`：纯标准库规划器，将角度配置展开为 20 ms 一点的 CSV，同时保存配置和 SHA256。默认只生成文件，不访问设备。
- `camera_servo_scan.h`：CPU 执行合同、完整 CSV 校验、心跳和异常停机；与主机 C++ 测试使用同一份代码。
- `camera_servo_native.cpp`：现有 ICraft ARM 入口增加 `scan`，沿用板卡身份核对、独占锁及 SDK 寄存器访问。
- `test_camera_scan.py`、`test_camera_servo_scan.cpp`：主机规划与模拟设备回归。

## 15–20秒录制目标参数

默认采用三层连续弓字扫描：先在俯仰 +30°时从水平 -30°扫到 +30°；保持右端水平位置，俯仰降至 0°，反向扫到 -30°；再保持左端水平位置，俯仰降至 -30°，扫到 +30°，最后回中。每层中途不停，不在水平扫描过程中大幅上下摆动。

根据15–20秒的新目标，两轴由上一轮30°/s放缓到标称20°/s，三层与水平范围保持不变。端点稳定时间0.2秒，不额外停拍，起始保持0.2秒、回中后保持0.1秒。共833个样本，计划总时长16.66秒：水平扫描9秒、两次切层3秒、到起点与回中共3秒，其余保持与标记1.66秒。这是完整指令计划，不是电机实测时间。

阶段03在录像出帧后保留0.5秒，再执行扫描，结束后保留0.5秒，计划录像约17.66秒。预检另计2秒调用余量，预算19.66秒；默认20秒是异常保护上限，正常完成即停止，并非固定录满20秒。`report.json`记录实际录像长度及是否达到20秒上限目标的`target_met`，未测前不能保证达标。旧网页独立的15秒自动停止设置未接入本扫描同步入口，不可直接并用。

假设相机真实输出60fps，20°/s时相邻帧标称转角0.333°，一段60°水平扫描3秒、约180帧，三层水平段共约540帧。17.66秒录像约1060帧，但重建仍按现有候选预算选帧，不是把所有相邻视频帧逐帧送入MVSplat。当前采集默认仍为30fps，不将未经探测确认的60fps模式设为默认；现场确认支持时加`--fps 60`。帧率高不等于曝光短，需额外核对拖影。

原慢速三层配置已另存为`camera_scan_bow_conservative.json`，仍为水平10°/s、俯仰5°/s、2303点及46.06秒计划。需要回退时显式选择该文件；同步录制同时改为`--max-seconds 60`，不可用15秒上限裁断慢速扫描。

水平端点脉宽为 1167、1833 µs，三层俯仰脉宽为 1833、1500、1167 µs。标称角度来自占位的 180°位置舵机映射；明天需用仪器和实物校准。软件日志中的 `requested` 是指令，`active` 是 FPGA 当前脉宽寄存器回读，均不是机械编码器反馈。

原单层逐点扇扫仍为 777 点、计划 15.54 s，可使用 `--profile video_input/camera_scan_profile.json` 生成；其 CSV 与原验证版本逐字节一致。

俯仰软件角度限制±45°，硬件和CPU脉宽限制均为1000–2000 µs。生成器仍检查每20 ms变化不超过10 µs，20°/s版最大5 µs，保留30°/s版最大7 µs，没有提高PWM频率或放松限位。首次先用已有`smoke tilt`核对方向和限位，再验证跟随与端点稳定；运动变快可能增加拖影，应保留足够照明并观察实拍，不能只以计划时间判断画质。

## 最短使用流程

以下命令在开发板的 `mvsplat` 目录执行。程序文件需与对应新头文件一起部署。编译只更新 ARM 程序，不生成或改写 BOOT。

```sh
sh video_input/build_camera_servo_native.sh
python3 -m video_input.camera_scan --output /tmp/instrument_scan.csv
video_input/camera_servo_native scan /tmp/instrument_scan.csv
```

第三条仅预览，正常输出 `DRY RUN; no device opened`。CSV 已存在时请换一个新文件名，避免覆盖上次计划。

只有新 PWM 固件已经加载并通过只读 `status`、J17 水平23/俯仰21/共地2接线不变、外部供电和机械安装已经确认后，才执行下列运动命令。先用既有单轴 `smoke` 确认小角度运动，再执行正式扫描：

```sh
video_input/camera_servo_native status
video_input/camera_servo_native smoke pan --execute --wiring-j17-23-21
video_input/camera_servo_native smoke tilt --execute --wiring-j17-23-21
video_input/camera_servo_native scan /tmp/instrument_scan.csv --execute --wiring-j17-23-21 --log /tmp/instrument_run.csv
```

每条依次运行，不并发。日志路径必须不存在；按 Ctrl+C/SIGTERM 会停止提交位置并尝试关闭两轴 PWM。CPU 失联则由 FPGA 500 ms 看门狗停止脉冲；停止脉冲不等于切断舵机供电或机械制动。

## 调整轨迹

修改 JSON 后重新生成 CSV 即可，不改 FPGA。

- `mode = raster`：逐点停留；`pan_step_deg` 决定水平点距。
- `mode = sweep`：起点稳定后连续扫向终点，途中不停；此名称指位置扫描，不是连续旋转舵机的速度模式。
- `tilt_rows_deg = [30, 0, -30]`：当前三层扫描，相邻层采用反向水平顺序，仅在水平端点换层。单层仪器测试可另存配置并显式改用 `[0]`。
- `pan_speed_deg_s`、`tilt_speed_deg_s`：独立的标称角速度；超出每帧脉宽变化预算会在设备打开前拒绝。
- `settle_s`、`dwell_s`：到点稳定时间、停留时间；`cycles` 控制重复次数，末尾自动回中。
- `calibration`：位置舵机的方向、每度脉宽和允许角度，中心固定为已约定的 1500 µs。

不能根据 YB-P25M 型号名直接认定实际角行程。默认配置没有假定水平能转360°。只有确认实际为360°位置版本、校准实际映射并确认线缆允许转动后，才可扩大水平范围。若实际为连续旋转版本，PWM 通常控制方向与速度，本程序会拒绝该类型，不能靠改一个角度数字获得准确定位。

## 螺旋扫描

`mode = spiral` 在同一段运动中同步改变水平与俯仰角度；先到起点，稳定后连续扫到终点，中间不逐点停顿，最后回中。它改变观察方向，不表示相机沿空间螺旋真实升降，也不代表产生了可用于三角测量的平移基线。

当前独立示例已按用户要求扩大为水平 -30°→30°、俯仰 +30°→-30°。保留俯仰速度上限5°/s，两轴同步后主体联动段计划12秒，连同到起点、稳定、停留和回中共1299点、25.98秒。这只是60°水平范围的局部螺旋段，不能称为已经完整转一圈。角度仍为未经过机械测量的标称值，硬件俯仰保护继续保持标称±45°。

在 `mvsplat` 目录生成计划，后面的 ARM 执行入口不变：

```sh
python3 -m video_input.camera_scan --profile video_input/camera_scan_spiral.json --output /tmp/spiral_scan.csv
video_input/camera_servo_native scan /tmp/spiral_scan.csv
```

第一条只生成CSV，第二条只预览；完成本文前述上板与仪器核验后，才可加 `--execute --wiring-j17-23-21 --log /tmp/spiral_run.csv` 执行。

`tilt_start_deg`、`tilt_end_deg` 控制起止俯仰，交换二者可改为向上扫描；两个速度参数都是上限，较慢的一轴会约束整段时间，另一轴同步降速，保证两轴同时到达终点。`settle_s`、`dwell_s` 只作用于两端，不会在螺旋主体中插入停顿。

若水平硬件确认支持360°位置控制，可校准角度映射后规划一个完整转角。程序不会把角度取模后从终点突然跳回起点，不能用这种回绕伪造连续螺旋。当前位置控制模式限制螺旋为一次不回绕的行程；真正多圈持续转动还需要确认电机类型、角度反馈和线缆方案，不能通过增大 `cycles` 冒充。已完成的一整圈纯软件规划检查不代表实物360°验收。

## 数据和节拍

CPU 将全轨迹校验完成后才允许打开设备；旧固件无 SRV1 身份或 ABI 不符时不写应用寄存器。运行前创建新日志，记录计划时间、单调时钟实耗时、事件、两轴目标脉宽、两轴生效脉宽、FPGA 帧计数和状态。读回值在 CPU 逐次采样，不代表同一硬件瞬间的原子快照。

ARM 运行在普通 Linux 下，位置更新不是硬实时。每次提交之后至少等待一个目标更新间隔，调度晚了不突发补交；实际扫描时间可能长于计划，日志保留真实差异。50 Hz PWM 脉冲本身由 FPGA 产生，不依赖 ARM 每周期翻转引脚。看门狗在刷新心跳之前及每次等待结束后检查，不能把超时清掉后继续冒充连续扫描。

`capture` 仅为到位事件日志，不会启动 USB 摄像头或拍照。当前可与已有摄像头录制入口配合使用；本增量没有修改录制网页或推理链路。连续录像可参考两个端点标记裁掉到起点和回中的片段。

## 仪器核验顺序

1. 舵机外供保持关闭，先加载新固件并运行只读 `status`；它核对身份、配置及软件采样的帧计数频率。
2. 用示波器/逻辑分析仪测 J17 23、21 对2，核对约20 ms周期、目标脉宽及信号电平；不能以软件回读替代实际引脚测量。
3. 外供恢复后先做单轴小角度试转，核对零点、方向和机械干涉，再跑默认扫描。明天再根据实测扩大范围。
4. 检查日志的实耗时、帧计数和中断/超时行为，保留仪器截图及实际角度记录后才算实板验收。

## 水平拍摄与三层覆盖角

此前保存的 HF868 去畸变后重建输入，使用 `calibrations/hf868_1280x720_20261102.json` 对应标定，其128×128准备图像的有效垂直视场约31.24°。镜头水平时，按居中光轴计算约覆盖向上15.62°至向下15.62°；这是由历史准备相机内参换算的几何范围，不是本轮光学实测。原始标定的未校正针孔估计约36.24°，不能替代当前去畸变和裁剪后的实际输入范围。

在相同镜头、成像模式和裁剪参数下，+30°、0°、-30°三层的垂直视场并集理论上约为 -45.62°至 +45.62°，但相邻层只重叠约1.24°，匹配与融合余量很窄。配置按用户要求保留30°；若后续跨层效果不稳，可缩小层间距，或保留±30°端点并增加中间层。录像保留换层过程也能提供过渡帧，但重建选帧是否使用这些帧仍需另行验证。上述角度不保证有效三维深度或全部区域画质，改变镜头、焦距、分辨率或裁剪后需重新核对。
