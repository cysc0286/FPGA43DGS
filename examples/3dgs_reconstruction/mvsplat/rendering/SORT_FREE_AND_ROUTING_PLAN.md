# 换视角渲染：免排序与 FPGA 物理优化分析

日期：2026-09-30。状态：论文、当前源码和已有布线报告核对；不是新增实板成绩。
范围仅为场景已常驻后的相机位姿到完整 RGB 返回。16k 预览与 32k 全量分开比较。

## 1. 先算能够省在哪里

`view_switch_v4/parallel_results.json` 中的 32k 全量平均为 45.212 ms。
其中收集 3.124 ms、深度排序 2.420 ms、Tile 计数与分发 3.126 ms；
FPGA 提交/执行/回读为 26.672 ms。“分组排序 8.671 ms”不是纯排序耗时。

假设其他阶段完全不变，仅将深度排序成本降到零，算术估计为
45.212 - 2.420 = 42.792 ms，即减少约 5.35%。它不是实测，也不是换合成
算法后的速度上限：新算法可能进一步缩短 FPGA 周期，也可能增加求值次数。
16k 预览之前为 31.932 ms，不能直接从它减去 32k 的 2.420 ms。

## 2. 三类不同的“免排序”

### 保留有序合成，减少排序次数或精度

当前合成递推为 C += T * alpha * color，T *= (1-alpha)，所以不同深度
颜色交换顺序一般会改变结果。直接删除 sort 仍执行原合成，不是正确的
免排序算法。

可实现的候选是深度分桶：按量化深度作一到两趟分组、桶间近到远，桶内
保持输入顺序。它仍有粗顺序，但可省精确排序；遮挡交界、相互穿插表面
最需要检查。优点是不用换现有 FPGA alpha 内核。

另一候选是排序复用。相机朝向 R 固定、只有平移时，中心深度满足
z_i = r3 dot p_i + t_z，因此 z_i-z_j 与平移项无关，数学上的中心深度次序
不变。缓存应覆盖整个所选场景，不能只缓存上一帧可见高斯；本帧仍需重新
投影、可见性筛选与 Tile 分配。FP32 深度相等/近似相等时的舍入与稳定 ID
次序需要单独处理，不承诺未经验证的逐位一致。转动时需重新排序、修复
局部逆序，或明确接受近似；不能把任意六自由度运动都当作可完全复用。

### Weighted Sum Rendering，WSR，ICLR 2025

论文用包含背景项的加权分子/分母替代有序 alpha 累积：

    A = c_B*w_B + sum(c_i*alpha_i*w(d_i))
    B = w_B + sum(alpha_i*w(d_i))
    C = A/B

各项在实数算术下可交换，多个硬件分支可分别求部分和再归并。
这为简化逐像素透射率递推、扩大并行提供可能；有限精度求和仍有误差，
加法累加器本身也有反馈延迟，需要多份部分和/交错像素处理。

论文画质来自对新表示、权重和视角相关透明度的优化，不是直接给原 3DGS
删排序。我们的 MVSplat 输出尚不含这些学习项。固定深度权重可先做无训练
诊断，但应称 weighted-blended 近似，不能称完整复现 WSR。潜在问题包括
错误透出背景、前后景混色，以及失去当前 alpha 提前终止带来的收益。
现有 CTU 裁剪、opacity 范围和终止条件必须随公式重新核对。

论文移动 GPU 平均 1.23 倍的结果仅作为文献事实，不用于预测本板帧时间。
WSR 可免深度排序，但仍可能需要空间分组/Tile 数据组织，不能把这些成本
也自动删去。

### StochasticSplats，ICCV 2025

对每个像素做随机透明度采样，保留通过采样的最近深度颜色，再将多个
样本平均。最近深度比较不要求先排好全部高斯。官方仓库有针对原 3DGS
场景的 ST 模式，以及面向专门训练/微调场景的 ST-popfree 模式。

这条路线适合把采样数作为速度/画质旋钮，先测 1、2、4 samples/pixel。
少采样会带来蒙特卡洛噪声；增加采样会增加计算和片上状态。若使用时间
累积，必须分别报告相机变化后的第一帧和若干帧稳定后的质量，不能等待
多帧后再声称单帧已经清楚。GPU 的深度测试/多采样硬件优势也不能直接
当成我们 FPGA 已有的能力。

## 3. 布线该看什么

当前最终报告 `pipeline/exp_rom/results/20260930/physical/after/domain_200mhz.rpt`：

- 共享 clk_pll_i 为 200 MHz，setup 最差 +0.034 ns。
- 路径为原厂 video read enable 到 BRAM enable，不是渲染算术路径。
- 数据路径 4.520 ns，逻辑 0.345 ns、布线 4.175 ns（92.366%）。
- 路径从 SLICE_X22Y14 经 X93Y31、X8Y6 到 RAMB36_X0Y1，存在较大跨度。
  两个主要数据网扇出分别 12/15；不能把它简单归因为上千负载的扇出问题。
- 渲染/DMA 路径 setup/hold +0.316/+0.050 ns。
- 全板 Slice 99.16%、LUT 76.84%、BRAM 85.47%；这是此前实现的资源数据。

因此下一步应分别看共享时钟路径和渲染路径，不直接根据渲染余量给全板升频。
高布线延迟需要结合拥塞热图、单网跨度和物理约束判断根因，不能只看百分比。

| 方向 | 原理 | 本项目落点与注意事项 |
|---|---|---|
| 每个 Lane 的运算器、状态 RAM、ROM 局部放置 | 缩短线路，减少跨区域交换 | 先看连接关系，再小范围 Pblock；过紧区域会增加拥塞 |
| 控制信号局部复制 | 一个驱动覆盖整片改为多个近距离驱动 | 只针对测到的关键数据/控制网；不复制 CDC 同步链 |
| 长组合链分段、寄存器重定时 | 降低每拍逻辑与连线总延迟 | 对齐数据与控制，比较周期总数与实际频率，避免短批次填排空更慢 |
| 降低集中互联与拥塞 | 分银行、分层分发，减少大多路选择器与大范围总线 | 不盲目增加 Lane；有些片上中间字段可以窄化，但 AXI 边界不必跟着缩窄 |
| 时钟与公共平台路径隔离 | 避免渲染频率受无关视频路径限制 | 独立时钟须配套 CDC/FIFO/复位及带宽验证，不能只改 XDC 数字 |
| 多组物理策略对照 | 由不同放置/复制/重定时组合寻找更好的路径 | 使用现有 Vivado 2018.3 和厂商流程支持的选项，不照搬新版/Versal 命令 |

物理布线改善只有转化为更高可运行频率，或支持更好的流水结构，才会减少
帧时间。固定频率、周期不变时，增加时序余量主要改善时序裕量。
一个仅供算术理解的例子：5.215 百万周期在 200 MHz 是约 26.08 ms，在
假设可实现的 220 MHz 是约 23.71 ms；节省约 2.37 ms，不是整帧加速 10%。
本板尚未验证 220 MHz，真实 DMA/DDR 开销也未必按时钟等比例下降。

更大的结构机会在 `render_lane`：装入 16 像素工作集、调用 evaluate_mini、
写回后才处理下一项。循环内部 II=1 不等于整个 Gaussian 序列每拍启动一个。
可评估多个独立 Mini-Tile 上下文交错，让一组等待累加结果时处理另一组。
同一像素的真实先后依赖必须保留；这属于流水架构优化，需要与纯物理优化
分开做归因实验。

## 4. 建议实验顺序

1. 固定相机序列，同时保存 16k 速度优先和 32k 全量两档基线；不得交叉比速度。
2. 原有 FPGA 上先比较精确排序、朝向固定时的排序复用、粗深度分桶。
3. 新公式单独对照：原场景 ST 低样本与固定权重 WSR 近似；比较遮挡、噪声、
   首帧质量与连续转动质量，再决定真正移植哪一种合成内核。
4. FPGA 先对照独立上下文流水；物理侧同步定位拥塞/长线，所有候选保留旧版。

每次报告相机到 RGB 的均值/P95/P99、纯排序、Tile 组织、硬件周期、
传输字节、时钟和最终资源/时序，以及对实拍 PSNR/SSIM、对精确渲染误差。
随机方法增加跨帧噪声、运动后首帧和稳定帧对照。不把省排序的理论估计、
HLS II 或更好的 WNS 当成已经上板的帧加速。
