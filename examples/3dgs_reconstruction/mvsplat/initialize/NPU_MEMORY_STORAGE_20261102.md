# NPU 主线内存与持久存储实板核验（2026-11-02）

本轮目标是解除存储满盘和 RAM 部署依赖，保留完整计算及正确的保护，并用实际结果选择配置。
分支 `feat/npu-memory-storage-20261102`，父版本 `0405f09`。四业务模块、四个 NPU 子图、CPU 回退、冻结 FPGA 和 BOOT 不变。
完整机器可读数据见 [本轮指标](NPU_MEMORY_STORAGE_20261102.json)。

## 已执行的变更

1. **安装包归档后清理**：审查 `/proc` 的映射、打开文件、执行文件和工作目录，并检查正式环境和冻结包的符号链接，没有发现依赖。
   将 `arm_packages` 的 299 个普通安装文件逐文件下载，核对长度和 SHA256，再重新核对板端身份后仅删除这些文件。
   释放 2,148,346,742 字节（2.001 GiB）；压缩包与恢复清单在电脑、Git 之外。
   `arm_mamba` 的约 7.8 GiB 本轮没有删除：已通过安装包达到释放约 2 GiB 的目标，无需再扩大清理面。
   正式 `arm_env`、模型权重、SDK、冻结渲染包和回退代码均保留。
2. **部署移到持久磁盘**：位于 `/root/fpga43dgs_reconstruction/npu_mainline_20261102`。
   初始复制核对 513 个文件，形成 `baseline/`、`current/`、`assets/`、`runs/` 和 `tmp/`；依赖仅指向原持久环境。
   BOOT 继续检查实际只读挂载媒体，`BOOT.reference.bin` 仅为证据副本，不代替真实媒体校验。
3. **减少代价体临时副本**：继续 16 个候选一组、全部 128 候选。无梯度推理中，复用可丢弃的 warp 输出做乘法，预分配相关体而不在末尾拼接。
   保持通道求和顺序和精度；梯度路径与混合 dtype 的原逻辑保留。不是删候选或降低分辨率。
4. **高斯归档可选磁盘暂存**：`MGS_GAUSSIAN_ARCHIVE=disk` 将待归档 NPZ 放持久盘，保留流式哈希和首帧后的逐数组回读验证。
   拒绝 tmpfs/ramfs 输出，错误只清理本次创建的不完整文件。默认仍为 `memory`，因为磁盘模式本次没有整体优势。
   现有 checkpoint mmap、临时 state 释放、CPU 模块代理替换已存在，本轮不重复计作新收益。
5. **更严格的身份和 PSS 监控**：receipt 绑定实际执行的生成源码，以及 `runtime.py`、`memory_runtime.py`。
   实板发现退出子进程成为 zombie 后仍有 `/proc/PID`、但已经没有 PSS 的竞态；仅重新确认 `Z`/`X` 才跳过。
   活进程、无法确认状态及零 RSS 的活进程仍须提供 PSS；其后代继续累计，未放松限额。
6. **保优回收**：新增 `initialize/result_retention.py`，默认仅预览。同协议、正确性/有限值/图像/内存均通过后，选择测得首帧时间最短者。
   先原子保存指标、哈希和失败摘要，再删除非优试验；运行中、显示中、显式回退、未标记或其他协议不误删。

## 实板时间与内存

同一公开视频、2 张上下文、3 张资格留出视角；完整保留 32768 高斯与 128×128 输出。
四个真实 NPU 子图为 `backbone_cnn / depth_head / to_gaussians / to_disparity`，3 推理线程＋1 准备线程、准备重叠、视频前合成预热。
预热和输入时间仅记录；场景准备严格为 `VIDEO_COMPLETE → FRAME_COMPLETE`。各配置仅完整测一次，不报告 P95 或显著性。

| 配置 | 视频结束到首帧 | 完整网络前向 | 进程树峰值 PSS | 系统最低 MemAvailable |
|---|---:|---:|---:|---:|
| 持久部署，原调度 | 20.559 s | 11.598 s | 524.1 MiB | 116.3 MiB |
| 缓冲复用，内存归档 | 21.056 s | 11.981 s | 503.0 MiB | 128.7 MiB |
| 缓冲复用，磁盘归档 | 22.538 s | 12.584 s | 511.4 MiB | 120.4 MiB |
| 缓冲复用＋回收旧 tmpfs，保留结果 | 20.075 s | 11.532 s | 565.1 MiB | 288.4 MiB |

前 3 组保留相同的旧 tmpfs 占用。缓冲复用的同条件单次观察为 PSS **524.1→503.0 MiB**，但首帧 **20.559→21.056 s**，不能称提速。
磁盘模式虽不保留 11,535,354 字节的待归档 Python payload，全程峰值并未进一步降低，总时间还更长；不将时间差全部归因于落盘，也不设为默认。

确认无人使用旧 RAM 部署、266 个持久回退/资产文件身份正确后，删除本助手专属旧目录，实际释放 **153.4 MiB tmpfs**，再运行第四组。
删除后全链仍跑通，四组高斯参数、完整 framebuffer 与 RGB 均逐字节一致。第四组 **20.075 s** 是本轮最快合格结果，仍比 20 s 多约 75 ms，不能声称严格达标或稳定加速。
第四组 PSS 反而为 **565.1 MiB**，同时系统最低可用内存提高到 **288.4 MiB**。PSS 与整体系统余量是不同指标；不能把 tmpfs 释放量直接从 PSS 中相减，也不能声称最后配置的进程峰值更低。
本轮确认的是单项缓冲优化的内存收益、持久部署可运行，以及明显增加的系统余量。

预热时长按每组原记录保存在指标 JSON 中，不参与最佳结果选择。限制始终为 PSS 700 MiB＋MemAvailable 96 MiB，设备侧仍预留 64 MiB 地址工作区，`DIRECT_SFB=0`。

## 标准使用方式

持久输出可显式尝试磁盘归档；生产默认继续内存策略：

```sh
MGS_GAUSSIAN_ARCHIVE=memory python pipeline.py initialize ... --out /root/.../runs/NEW_RUN
# 只有需要进一步减少待归档对象时再显式选 disk；tmpfs 输出会被拒绝。
MGS_GAUSSIAN_ARCHIVE=disk python pipeline.py initialize ... --out /root/.../runs/NEW_RUN
```

实际四子图生成入口继续使用 `--backend npu --partitions backbone_cnn depth_head to_gaussians to_disparity`，
`--npu-acceptance` 指向本轮新代码资格文件；旧源码 receipt 会被拒绝。原图、权重、编译产物、桥接库和环境复用当前平台已验证路径。
已有完整复跑命令保留于电脑 `outputs/npu_memory_storage_20261102/optimized_after_reclaim/command.txt`，不含密码。

实验回收必须先由生产者写 `memory_trial.json` 标记、确定同一协议和四个验收门槛，并确保没有运行中的写者：

```sh
python -m initialize.result_retention --root RUNS --protocol FIXED_PROTOCOL
python -m initialize.result_retention --root RUNS --protocol FIXED_PROTOCOL --apply
```

显示中/必要回退的结果用 `--protected NAME...`。此工具不扫描用户录像库或软件环境。
