# MVSplat 板端视频到渲染闭环验证

本页是完整 SfM 质量基线。后续同日快速几何与单进程版本已完成实板运行，首图 66.68–79.93 秒，但第一视角未过质量门槛，不能替代本基线。当前一分钟目标及版本对照见 [FAST_VALIDATION](FAST_VALIDATION.md)。

本记录对应 `runs/mvsplat_arm_full_v1`，测试于 2026-09-29 完成。输入是板上存储的 3 秒、10 fps、30 帧 RGB 室内视频。整条生产链都在悟净 30TAI Lite 上执行；电脑只通过 SSH 发起命令、收集证据，并在完成后计算独立渲染参考与画质指标。运行未使用 GPU、NPU 或逐场景反向训练。冻结 FPGA 渲染包、BOOT 和位流未改。

## 结果

板端实际执行 `视频抽帧 → CPU COLMAP SfM → CPU MVSplat 预训练推理 → 高斯和相机导出 → CPU 投影/分组/排序 → FPGA 求值与合成 → 目标视角图像`。30/30 帧注册，1145 个稀疏点，平均重投影误差 0.4383 px。网络用第 0、29 帧作为输入，生成 32,768 个高斯；第 7、15、22 帧不输入网络，用作目标视角，但已参与 SfM，因此不是完全未见几何。生成的世界坐标协方差重建相对误差最大 4.77e-7，opacity 误差最大 1.23e-8，SH0–SH3 系数逐位保留；冻结后端不支持 SH4，导出时截断四阶，三视角与完整 SH4 的参考差异为 89.42–89.65 dB。

| 板端阶段 | 壁钟时间 | 采样进程树峰值 RSS |
|---|---:|---:|
| 视频抽帧 | 11.23 s | 118.75 MiB |
| CPU SfM 与去畸变 | 156.97 s | 480.36 MiB |
| 相机/图像准备 | 6.45 s | 416.67 MiB |
| MVSplat 加载与推理/保存 | 57.71 s | 529.09 MiB |
| 高斯/相机导出 | 6.68 s | 110.57 MiB |

MVSplat 内部加载/设置 28.20 s、实际网络推理 22.14 s，剩余是保存、启动及监测等开销；未把 22.14 s 冒充整阶段时间。从视频启动到首张 FPGA 图像约 249.43 s；三目标视角各预热一次并分别重复三次 CPU/FPGA 后，验证总壁钟约 342.69 s。峰值进程树 RSS 均低于预设 650 MiB，最小系统可用内存为推理阶段约 303.73 MiB。

每个时延是同一模型、同一目标视角、预热后 3 次的均值。定时段由冻结包 `render.py` 统计：属性预处理、分组排序、渲染子进程，不包含外层 Python 启动等；进程级壁钟由独立板端监控器统计，包含整次命令启动与退出。两种口径不能混为一谈。全部 24 次渲染完成，3 次重复的帧缓冲哈希在各视角/后端内一致；24 个结果哈希与回收文件再次核对。FPGA 对板端 CPU Dense 为 54.25–55.00 dB，SSIM 0.9995–0.9997。

板端执行后，`evaluate.py` 仅为解释计时口径及补充局部误差而修改并重新读取同一批原始输出；最终 `evaluation_v3` 是事后分析，没有重新运行或更换板端渲染代码。运行时的其余源码哈希与归档文件核对一致。

三视角 FPGA 对原视频的 RGB MAE 为 0.0587、0.0406、0.0363，最差 16×16 区块 MAE 为 0.3081、0.1997、0.1098；对独立 SH3 参考的 MAE 为 0.00239、0.00205、0.00222。图像可辨认室内布局，但有模糊、近处遮挡边缘伪影；当前 20 dB / 0.7 SSIM 门槛是这一次小场景的最低工程闭环门槛，不代表高保真、多场景泛化或实时建图。见 [四列效果图](../runs/mvsplat_arm_full_v1/evaluation_v3/comparison.png) 和 [完整逐视角指标](../runs/mvsplat_arm_full_v1/evaluation_v3/quality_and_timing.json)。独立参考是 NumPy 世界协方差/SH 实现，并非作者 CUDA 渲染器。

## 失败与修正

未经内存改造的 ARM 128×128 推理在 650 MiB 监控阈值被终止，峰值 650.35 MiB，不曾得到输出。随后将 128 个深度假设按 16 个分块生成代价体，同时使用内存映射权重并在加载后释放临时 state；不减少深度候选、模型层或精度。电脑上原/分块两种执行的 means、covariances、SH 和 opacity 全部逐位一致；电脑采样峰值 RSS 667.46→478.76 MiB。相同输入的 ARM 分块独立测试在 520.47 MiB 峰值下完成，网络推理 20.89 s；其与电脑输出不是逐位一致（例如 means 最大绝对差 0.00254），属于跨架构数值差异，不能写成 ARM/电脑逐位相同。完整板端视频重跑的峰值和网络推理分别为 529.09 MiB、22.14 s。

另保留 256×256 电脑推理→板端渲染的版本：131,072 高斯、24 次渲染及冻结示例逐字节回归均通过，硬件对独立 SH3 参考约 46.8–47.1 dB，但目标帧对原视频仅 17.77、19.61、20.94 dB，前两帧未过同一重建质量门槛。不能把该配置标成验收通过。128 与 256 的输入、生成点数和场景画质不可混报。

## 判断与下一步

本轮证明固定权重 MVSplat 可在板端 ARM CPU 内存预算中运行，并真正连接已有 FPGA 渲染器；无需先接 NPU 才能形成板端闭环。性能尚不理想：SfM 157 s 是首图最大单阶段瓶颈，网络纯推理 22 s；即使单独把 22 s 推理归零，249 s 首图也最多约 1.10x。现有每视角重新启动渲染程序，使定时段 1.37x 的硬件优势缩小为进程级约 1.03x。下轮应先做常驻多相机渲染入口及端到端对照，然后评估 SfM 匹配/重建加速；MVSplat 网络中卷积与代价体计算是 NPU 候选，但必须先核实 ICraft 算子支持、数值误差、模型/特征搬运、内存和真实端到端收益。没有 NPU 推理数字，也没有新增 FPGA 资源、时序、功耗数据。

复跑、接口和锁定来源见 [README](README.md)。证据保留在 `runs/mvsplat_arm_full_v1`、`runs/mvsplat_nyu_128_v1`、`runs/mvsplat_nyu_v1` 与 `evidence/mvsplat_arm_deploy_20260929`。五项坐标/协方差/SH/终止规则测试通过；板端运行配置及监控阈值见 `pipeline_result.json`，验收阈值见 `acceptance.json`。
