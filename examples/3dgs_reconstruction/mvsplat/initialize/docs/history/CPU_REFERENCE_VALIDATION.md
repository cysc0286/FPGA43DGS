# CPU 视频重建参考链：实际验证记录

日期：2026-09-28。**已完成电脑 CPU 的视频→位姿→高斯优化→模型/相机导出，并用首轮新模型完成两视角 ARM CPU 渲染。** 输入没有使用深度、已有位姿或预训练高斯。板端完整建图/训练尚未移植；本轮没有 NPU、FPGA 性能或功耗实验。

## 输入、版本和测量边界

- 输入：[SuperPoint 作者仓库的 NYU 原始 RGB 片段](https://github.com/magicleap/SuperPointPretrainedNetwork/blob/1fda796addba9b6f8e79d586a3699700a86b1cea/assets/nyu_snippet.mp4)，3秒、10fps、30帧、640×480。这里只使用其视频，不使用 SuperPoint 网络。SHA256 `0a7e3c684e917dd937ae1ec6c64f770c111b939f08f020b66965c1fccf9ae86a`。
- 几何：pycolmap 4.2.0，`has_cuda=False`；特征、顺序匹配、BA均CPU。SIMPLE_RADIAL单相机，去畸变后PINHOLE，初始三角化角度门槛4°。
- 优化：OpenSplat 1.2.2，提交 `62fd86fe3b62644b65890557ad9bf397abdc7cfb`，CPU Release原版源码，PyTorch 2.7.1+cpu。1000步、SH0、最多20,000个高斯，100–750步间每100步增密/剪枝；黑背景、默认L1＋SSIM损失。
- 训练图：320×240，主点159.5/119.5；29帧优化，`frame_000015.png`留出。留出帧仍参与SfM及初始点颜色估计，因此不是完全隔离的泛化评估。
- 主机：Windows，Intel Core i9-14900HX，约32GB物理内存。OMP/MKL线程设为8；OpenSplat自有光栅线程按硬件并发数调度，不能将其误称严格8线程测试。
- 时间由Python单调时钟测量子进程生命周期，包含该阶段启动/文件I/O；训练还包含每10步验证预览输出。RSS为每0.1秒采样的进程树工作集峰值，可能漏掉短暂尖峰，不是模型参数量或ARM内存。
- 编译、下载、环境配置、评估和SSH传输不计入阶段时间之和。两次为独立功能运行，无专门预热；不据两个样本给P95/P99或稳定FPS。

## 模型与相机接口验证

首轮模型12,129点的原有字段全部逐位保留，高阶SH补零，所有值有限。30台相机与OpenSplat保存相机交叉比较：旋转最大绝对差 `3.35e-8`，位置最大绝对差 `3.70e-7`，属于float导出差异。详见 [适配验证](evidence/nyu_cpu_v1/adapter_validation.json)。

训练模型保持COLMAP坐标系；目标相机同时包含位置、朝向、内参。图像重采样与内参/2D观测同步变换，未静默丢弃畸变或主点。新视角在相邻两台相机位置中点，旋转投影回SO(3)；没有该精确视角的真实照片，不报告该视角PSNR。

## 首轮模型的板端 CPU 渲染

板端四核Cortex-A53，Linux可见993MiB、本次检查可用约751MiB、无swap。[环境记录](evidence/board_environment.txt)。调用已有冻结包的 `cpu_dense`（4线程）。本次未修改位流，也未使用NPU或FPGA计算。

|板端指标|留出帧相机|中点新视角|
|---|---:|---:|
|输出分辨率|320×240|320×240|
|PLY读取与投影阶段进程耗时|117.36 ms|67.52 ms|
|分组/排序阶段进程耗时|35.36 ms|35.44 ms|
|CPU渲染阶段进程耗时|768.88 ms|418.42 ms|

|显示域对留出实拍帧SSIM|0.913421|无对应真值|

|显示域对OpenSplat量化参考SSIM|0.998889|未测|

各视角只执行1次，顺序不同且有缓存、进程启动和频率状态影响，不能由921/521ms宣称优化或稳定FPS。包内总耗时从属性程序启动计至framebuffer生成，排除包SHA检查、SSH、上传和最终PPM编码。原始日志：[留出视角](evidence/nyu_cpu_v1/board_cpu/frame_000015/result.json)、[中点视角](evidence/nyu_cpu_v1/board_cpu/novel_midpoint/result.json)。

数值诊断：原始framebuffer最大RGB为1.505，约14.96%的通道超过1。OpenSplat本身在forward末尾裁剪RGB至1，而冻结包在写PPM时裁剪。初次用未裁剪raw对PNG比较只得到21.0775dB；这不是显示图像质量。现按双方已有显示行为统一到[0,1]后为27.9467dB，并保留 [未对齐口径的原始诊断](evidence/nyu_cpu_v1/quality_before_display_alignment.json)。没有为了抬高指标修改模型或渲染算法。对OpenSplat图像不是逐位一致，局部最大差仍有0.0919；算法包围框/截断与PNG量化等差别需要后续精确参考继续分析。

这次的改善是从“只能加载已经训练的场景”前进到“由RGB视频帧实际建立新高斯场景并接回板端渲染”，没有GPU依赖。房间结构、家具和透视关系已经可辨认；SH0、低分辨率和短优化使反光、高频纹理、椅子细杆和窗边仍有模糊/局部误差。3秒短片仅覆盖室内一个角落，不能证明完整房间、未观察表面或动态场景重建。

资源代价也明确：训练工作集约1.72–1.78GiB，超过目前板端可用内存，不能原样上板。本轮不使用额外FPGA资源；没有新增LUT/FF/DSP/BRAM与时序测量。CPU占用率完整时间序列、主机/设备带宽、LPIPS和功耗均未测，不声称加速或节能。下一增量应保持本路线，先分析运行时与缓冲内存、减少峰值并验证ARM依赖，再讨论板端训练速度；不能把减少高斯参数数组等同于同比降低整个进程RSS。
