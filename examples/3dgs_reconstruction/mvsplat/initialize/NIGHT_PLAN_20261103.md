## 先解决展示范围

真实输入是在原地旋转一周，展示观察点固定，只改变朝向。它没有可靠三角测深基线；这是固定中心角度预览，不能声称已经恢复可任意平移观察的完整三维空间。

用户进一步明确：需要将多组两两图像预测的 Gaussian 汇总，而非固定只做两组对比。新增 `--ring-pairs 8 --ring-auto-coverage --ring-candidates 64 --ring-min-pairs 8`：8 是组数预算与最低组数，实际按最终裁剪视锥的覆盖增益选择图像对；最低组数满足后继续补足，以免几何射线目标过早终止。图像估计旋转、相机平移为零，禁止伪造位姿或把一周均匀时间直接当真实角度。各组使用同一个预训练模型与真实 NPU 会话，不重载权重；统一旋转坐标和原点。重叠区域按来源方向选留，不平均不可观测的深度。总点数预算为 65,536，均匀减点是显式有损操作；组数增加不令全部未筛选 Gaussian 同时驻留。显式 1/2/4 组保留回退；采集服务的部署配置也固定采用 8 组。

后续 USB 实测必须沿用同一采集姿态：拍摄中心和高度尽量固定，只绕竖直轴慢速转满 360°，保持俯仰/变焦不变，不边走边拍。当前流程只估计旋转并将平移固定为零；若相机中心明显移动，不能按固定中心环视结果解释。录制页已显示该拍摄约定。

有限组数可能存在未覆盖扇区。输入候选、实际重叠或组数预算不足时，记录 `target_met=false` 和停止原因，不强行补空白。水平 360° 控制仅表示可选择所有方向，既不代表视频覆盖了球面上下方向，也不表示输出没有空洞。页面显示实际方向、按真实 c2w/K 投影计算的 1° 水平射线采样覆盖与最大连续空缺，以及近似深度边界。此覆盖是视锥几何估计，不能替代最终渲染画质。

历史一次前向约 9–10 秒；两组仅推理约 18–20 秒、四组约 36–40 秒是推算，不是新测或承诺。20 秒仍是争取目标。分别记录全部选定帧组到首个完整 RGB 的场景准备时间、单组前向、位姿、融合、场景加载、首帧与常驻换向延迟。

每组改为经过数组内容校验的内存交接，首帧前不生成 Gaussian NPZ；最终合并归档在 FRAME_COMPLETE 后保存并逐字段校验。数组内容身份和 NPZ 文件身份分别保存，不能互换摘要来跳过校验。此改动已通过软件回归，收益尚待新视频实测。

## 真实视频 A/B 输入下的整图 NPU 诊断

为检查此前的陈旧输出是否只由合成零输入造成，本轮从同一获授权的原地旋转游戏视频中取两个不同的真实视图对，在板端 ARM CPU 分别跑完整参考前向并捕获 `corr_refine_net` 与 `refine_unet` 的边界张量。checkpoint SHA-256 为 `83d0d9eaa753fa4a1f925288dc1f90b8c3297fad0ab0f6ed1f11a1c5946da25a`；A/B 的模块输入和 CPU 参考输出均不相同、形状一致。CPU 参考前向耗时 A 20.126 s、B 18.801 s。证据位于 `outputs/npu_unet_diagnostics_20261103/real_context_pair_cpu_reference/`。

两个已编译整图均在同一 NPU SDK 会话按 A×3、B×3、A×3 顺序运行，结果为诊断性负例，未进入正式分区：

- `corr_refine_net`：9/9 调用完成。A 初始三次位级一致；切换到真实 B 后第一次输出仍复用 A 的哈希，后两次变为另一输出；返回 A 后第一次仍是 B 输出。A 对 CPU 最大绝对误差 0.1452、RMSE 0.009663，越过严格逐元素门槛的比例约 91.74%；全序列最大误差 4.1684、RMSE 0.3088，门槛失败。输出没有稳定跟随输入，不能据耗时称为加速。
- `refine_unet`：9/9 调用完成，A、B、返回 A 的输出哈希全部相同，无法区分两个真实输入。相对 CPU 参考最大误差与 RMSE 均约 `3.401e38`，100% 元素超门槛，属于无效输出，不能作为性能结果。
- ETM 关闭控制使用独立诊断版桥接库，正式库未改。相同 A/B/A 测试下，两个模块的输出模式和错误指标未改善；因此“中间特征复用导致陈旧输出”仍是假设，尚无证据支持。ETM 诊断进程树峰值 PSS 分别约 130.7 MiB（corr）和 244.0 MiB（U-Net），最低系统可用内存分别约 656.2 MiB 和 592.3 MiB。
