# 环视画面不均匀：定位、修复与验证

本页冻结上一轮“覆盖面积补偿”结果。后续默认候选已升级为邻近高斯信息归并；新指标、回退和板端未验收状态见 [残余黑纹验证](RING_BLACK_STRIPES_20261112.md)，不能混用两版结果。

## 结论与证据范围

两张图作为 MVSplat 输入不是本轮确认的错误。实际流程是每对图像预测一组高斯，各组按同一个旋转坐标系合并，随后统一渲染，并非拼接多张已渲染图。MVSplat 的两视图前向负责组内预测，不能自动保证多个独立帧对在一圈内的深度和外观一致。[作者项目页](https://donydchen.github.io/mvsplat/)

本轮通过受控消融确认，**预算裁减会制造周期性采样条纹、损失像素覆盖，而且每个源视角保留率不同，导致方向间的亮度和细节损失不均匀**。默认候选增加覆盖补偿；没有改变网络、位姿、帧对、源图像或 FPGA 内核。跨组深度一致性、硬切接缝与纯旋转深度不可观测仍是独立问题，不能宣称全部修复。

本轮是本机 CPU 数值回放及接口验证。板卡 192.168.126.49:22 探测未连通，没有运行新 NPU 推理或生成新 FPGA 帧。下述时间不能作为板端性能成绩，历史板端画质／时延也不能与本轮 CPU 回放直接混用。私有视频、图像、高斯和逐帧原始证据均留在仓库之外，不提交 Git。

## 可重复的失败信号

固定两个相反源视角，每个视角为 128×128 个均匀高斯，使用生产 `angular_owned_indices` 和已有 `rendering.reference.render`。固定输入、相机、颜色、协方差与预算，比较裁减后平面相对未裁减平面的亮度。

旧的半数点预算使用 `np.linspace` 在展平数组上取点，出现 63 列没有高斯中心，内部列均值亮度变异系数 0.399788。该图像级检查实际失败；新增生产边界测试亦先失败后修复。空中心列不等同于整列黑像素，图像级结果由完整投影与透明度合成另行确认。

仅改成二维抽样在平面上能消除竖条，但真实六视角 SSIM 反而下降，因此没有直接采用“所有情况下都换二维抽样”的方案。

## 最终候选机制

1. **保留率可追溯。** 在角度归属筛选后、点预算裁减前，记录每个源视角的有效点数；再记录实际保留点数，两者之比确定补偿强度。不会使用目标图像、PSNR、场景名称或测试编号决定策略。
2. **有条件的二维抽样。** 保留旧的一维抽样作为常规路径。若其将本来有足够候选的整行／整列清空，且二维 2×2 分块、配额分配和交错保留能减少此类空洞，则采用二维候选。二维候选仍只选择既有参数，点数精确受限；边界外和原先缺失的区域不补画。
3. **补偿覆盖范围。** 对保留率为 p 的源视角，目标投影协方差为原有效投影协方差的 1/p 倍。渲染器原有的 0.3 像素方差低通项也参与计算；只扩大原三维协方差会漏掉该项，对小高斯尤其不足。利用实际源相机的朝向、焦距和高斯深度，将新增滤波范围转换回世界坐标协方差。
4. **边界不变。** 不新增推理调用，不更改位置、SH 颜色或透明度，不拟造平移、不推断新深度；补偿后的协方差进入原有内容哈希、存档验证、格式转换和常驻渲染接口。未裁减源视角的协方差逐位保持不变。补偿近似恢复覆盖，允许模糊细节，不保证恢复全部纹理或跨组几何。

## 同条件真实视频回放

采用原游戏视频已保存、已裁去隐私区的六组上下文图像，固定原内参、旋转位姿、预训练权重、128×128 输入、深度候选与渲染约定。每组只做一次 CPU 前向并保存原始完整高斯，后续所有版本复用同一组张量。六个目标帧不作为网络输入，但参与过旋转登记；本轮选型也使用了它们，所以这是开发／验证回放，不是独立测试集。

画质由同一个 NumPy SH3 有序 alpha 数值参考计算，显示限制在 RGB [0,1]。表中是六视角 PSNR 与 SSIM 的算术平均，均不是新 FPGA 输出。

| 方法 | 最终高斯数 | 平均 PSNR / SSIM |
|---|---:|---:|
| 原一维裁减，无补偿 | 59,445 | 15.4705 dB / 0.510072 |
| 全部改二维抽样，无补偿 | 59,445 | 15.2804 dB / 0.439572 |
| **有条件抽样＋覆盖补偿** | **59,445** | **19.6757 dB / 0.620833** |
| 保留角度归属后的全部有效点 | 101,527 | 19.6473 dB / 0.658354 |

最终候选由真实 `generate_ring` 内存交接入口回放，不只是单独运行补偿原型。六个视角的 PSNR 和 SSIM 均超过原方案；PSNR 单视角增益 2.3592–6.6707 dB。保持全部有效点的 SSIM 更高，说明补偿仍不能完全代替真实样本；该配置未经过板端容量与延迟验收，不直接替换现有点预算。

上述最终抽样策略在这六组真实数据上保留了原抽样索引，因此本组画质改善来自覆盖补偿；它没有凭空证明二维抽样普遍更好。另一个二维抽样加补偿的消融为 19.5534 dB / 0.589750，也未选为默认。

## 图像、格式与代价核验

- 平面回归覆盖每视角 4,096／5,461／8,192 点：最终策略没有清空原来充分覆盖的源图像列，列均值亮度变异系数分别约 0.0000310／0.0009584／0.0000424；相对完整平面的平均亮度约 0.9473／0.9489／0.9216。仍存在像素级误差，不能理解成无损。
- 实际 59,445 点通过原 `gaussian_rows` 接口；协方差分解与重建的最大逐高斯相对 Frobenius 误差约 4.75×10^-7，没有特征值裁剪。原始输入张量未被修改，最终内容身份、延后存档和回读校验正常。
- 数值参考的六帧候选求值总量从 29,853,179 增至 34,189,312，约增加 14.5%；接受贡献从 1,247,939 增至 2,073,144。更大的覆盖范围可能增加 FPGA 工作量；这些计数不是硬件周期、DDR 流量或板端时延。
- 推理调用数、最终高斯字段数和导出行数不增加。新增协方差数组及临时量有软件内存代价；板端 PSS 峰值、可用内存、首帧时间与换视角时间未重测。冻结 RTL／位流未改，无新增综合资源报告；功耗未测。
- 相关单元、图像输入、旋转图、常驻网页、环视协调、部署结构与渲染接口共 105 项回归通过；最终检查结果保存在仓库外的 `outputs/ring_uniformity_20261112/RESULT.json`。

## 回退与后续验收

代码仍位于既有 `gaussian_generation` 模块，`sampling.py` 已加入正式源码打包清单，板端同步清单会自动收录。没有修改网页、视频入口、NPU 编译图或冻结渲染包。

`generate_ring(..., sampling='legacy_linear', footprint_compensation=False)` 精确回到原抽样及未补偿参数；`sampling='spatial'` 可重复二维候选。默认 `sampling='balanced', footprint_compensation=True` 是本轮本地回放通过的候选，**当前已运行的板端服务未被替换**。

板端恢复后，先用同一已保存视频比较原版与候选：实际 NPU 输出、所有固定朝向画面、FPGA 格式转换、PSS/可用内存及换视角延迟。之后再决定是否增加点预算或调整帧对与跨组融合；不能用局部修复覆盖剩余接缝、深度或未观测区域问题。
