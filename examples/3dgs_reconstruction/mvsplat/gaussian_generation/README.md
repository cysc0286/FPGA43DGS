# 高斯生成

runtime 常驻固定 MVSplat；upstream 加载原始网络；memory 管理已有代价体调度；adapter 校验并转换 Gaussian／相机 ABI。
npu_branch 包含正式 ICraft 运行、图构建、资格和定位数值问题所需工具，测试集中于其 tests。
主线为四个既有局部子图加六个 Transformer FFN；其余计算仍在 CPU，CPU 显式回退继续保留。
拒绝的 corr/refine 等候选仅供相关诊断，不是默认已合格实现；严格 TF32 失败事实不因整理消失。
详细分工与数据接口见根 docs/CODE_STRUCTURE.md。历史 Windows 参考锁文件只作记录，不用于板端安装。

环视仍是两帧预测、多组合并、统一渲染。`sampling.py` 处理预算裁减后的像素覆盖：
仅在一维抽样产生整行／整列空洞时改用二维分块抽样；默认再将预算外的邻近高斯归并到保留点，
汇总其颜色、透明度和投影分布，不再只删点或统一扩大尺寸。网络权重、推理组数、总点数预算及渲染 ABI 不变。
该近似会改变位置、SH、协方差与透明度，可能平滑细节；局部颜色与几何仍不保证跨帧组一致。
`reduction='footprint'` 恢复上一轮面积补偿；`sampling='legacy_linear', footprint_compensation=False` 恢复原始删点。
代码候选已通过本地 CPU 回放；当前板端服务未替换。先前消融见 [均匀性验证](RING_UNIFORMITY_VALIDATION_20261112.md)，
新候选的画质、条纹、工作量与未测边界见 [残余黑纹验证](RING_BLACK_STRIPES_20261112.md)。

区域接缝另由 `blending.py` 处理：只在真实源相机视锥重叠内保留相邻来源，按角度差与图像边缘置信度
渐变分配透明度，仍逐组生成并汇成一个场景；不拼接源照片，不补画未观测方向，也不拟合跨组深度。
场景准备入口 `prepare_ring_scene` 的本地候选默认 `transition_degrees=8.`，设为 `0.` 恢复硬切换。
底层 `generate_ring` 仍默认 `0.`，便于既有调用和历史结果复现；独立调用需显式传入 `8.`。
配置的总预算仍为 65,536 点，本次实际保留点数和参考求值量有所增加，不能视作无成本改善。
六视角画质、接缝探针及数值验证见 [过渡融合验证](RING_TRANSITION_VALIDATION_20261112.md)。

`appearance.py` 增加可选的上下文颜色修正：从实际输入视角检查整个合并场景的渲染残差，
只对有效覆盖内的低频误差限幅，再按共同方向写回高斯SH常数项。位置、协方差、透明度与高阶SH不变。
原生渲染器提供线性RGB和覆盖率，不用显示PNG代替线性帧，也不使用评测目标帧拟合。
直接入口 `initialize` 的环视模式与网页双输入入口默认启用强度1；`--ring-appearance-strength 0` 回退至此前颜色。
普通双帧非环视模式不启用。底层函数仍默认关闭，供既有接口与历史对照使用。
当前候选在六个开发视角均有画质收益，仍有窄接缝；准备阶段增加每个输入视角的一次内部渲染，
换视角时仍只渲染一个合并场景。独立板端部署已通过真实NPU生成与FPGA校色／渲染验证；
当前展示场景已包含校正，后续采集与上传入口也会传入同一配置，详见 [颜色修正验证](RING_APPEARANCE_VALIDATION_20261112.md)。
