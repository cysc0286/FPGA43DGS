# 快速板端视频到高斯与渲染

2026-09-29 实板验证。当前目标是离线视频全部在板端处理，约一分钟内得到首张可用新视角；先部署链路，再优化延迟。不依赖电脑或云端生成位姿/高斯。电脑只发起命令、取回结果和事后计算质量。测试为同一段室内 RGB 视频，3 秒、10 fps、30 帧，SHA256 `0a7e3c684e917dd937ae1ec6c64f770c111b939f08f020b66965c1fccf9ae86a`。

## 部署与边界

```text
ARM 视频解码、首尾参考帧选择
 → ARM SIFT 双向匹配、Essential 相机与三角化
 → ARM 目标帧 PnP
 → ARM 官方 MVSplat 固定权重前馈
 → ARM 世界协方差/SH 转换、PLY/相机导出
 → ARM 属性投影、Tile 分组与深度排序
 → FPGA 求值、筛选、提前终止与有序合成
 → 图像
```

网络仅看第 0/29 帧，第 7/15/22 帧用于目标位姿与画质核验，没有输入网络。使用约 1196 万参数的原完整权重，128×128 输入，128 个深度假设按 16 个分块，输出 32,768 个高斯。没有逐场景训练，没有 NPU/GPU 推理。单进程版本合并准备、推理、导出，优先导入 Torch 修复 ARM OpenMP 静态 TLS 错误；没有引入常驻服务。

完整 SfM 路径保留为质量基线。快速路径不再注册全部 30 帧，只用首尾两视图的共同几何生成局部模型，尚未实现多帧组融合、全视频覆盖和长视频建图。目标相机来自同一视频，三张目标帧排除网络输入但参与 PnP；不是独立场景泛化测试。

均为从板端入口开始处理现存视频，到首张 FPGA 结果完成的壁钟时间，包含环境/库加载、位姿、推理、导出及首次渲染，不包含视频传到板子的时间。每种配置仅一次端到端运行；不是重复样本均值，也不支持稳定 P95/P99。没有重启系统、清除文件缓存或锁定温度/频率，不能从这几个单次结果推断稳定冷启动加速。完整 SfM 基线来自同日上一轮，未在快速轮重新测量。

单进程默认版本相对历史基线首图缩短约 73.3%（3.74 倍），同时改变了几何算法和覆盖范围；这不是纯 FPGA 加速。与同几何分阶段版本相比缩短约 10.5%，但内存增加约 67 MiB。默认单进程内部准备 6.68 s、网络加载设置 13.95 s、前向 14.71 s、导出 5.79 s；还要计 Torch 提前导入、启动/保存/监控等，不能只将这些内部计时相加冒充总壁钟。首次渲染监测约 8.7 s，后续单次渲染进程约 3.77 s。

焦距对照的 0.9262 来自同一视频先前 SfM 焦距，仅用于相机参数敏感性试验，仍假设零畸变，不是独立相机标定或可泛化的默认值。其前向为 21.23 s，而默认单进程为 14.71 s；CPU 时间约 39.96/41.08 s，当前壁钟差异尚未归因，不能声称焦距本身让网络计算变慢。

默认分阶段与单进程的网络输入、生成参数和各目标 CPU/FPGA 帧缓冲哈希相同，融合没有改变数值。默认单进程 FPGA 相对板端 CPU Dense 的 PSNR 为 54.77/52.36/54.28 dB，SSIM 为 0.99962/0.99950/0.99954；最大局部像素差仍达约 0.091，不能只凭高全局 PSNR 宣称逐位一致。对原视频 RGB MAE 为 0.06570/0.04668/0.04337，最差 16×16 区块 MAE 为 0.2953/0.2329/0.1517，图像有模糊、遮挡轮廓和边界黑区。质量损失来自上游几何/输入及生成模型的组合，尚未通过独立位姿真值归因。

快速默认三视角渲染定时段 FPGA 272.31/271.69/272.00 ms，CPU Dense 372.20/372.02/372.26 ms，加速 1.367/1.369/1.369 倍；此计时包含属性、分组排序和渲染子程序，不包含外层启动。完整独立进程约 3.77/3.87 s，优势仍约 1.03 倍。每视角/后端一次预热、一次测量，本轮不能据此报告稳定吞吐、P99 或常驻交互 FPS。

默认单进程导出协方差最大相对误差 4.76e-7、opacity 最大误差 1.23e-8，位置和 SH0–SH3 逐位保留，通过既有转换门槛。原始 SH4 保存、导出截断为 SH3；快速轮没有新增独立 SH4/SH3 渲染参考，不沿用慢速轮数值宣称快速 SH 截断已单独验收。

FPGA 逻辑、BOOT、频率与资源配置均未改。Slice 99.99%、200 MHz 自定义路径 setup/hold +0.310/+0.054 ns 是冻结后端的历史构建记录，原厂 AI 脉宽违例仍保留；本轮没有重新综合/布线，未新增资源利用率、功率、能耗或 DDR/DMA 总字节实测。进程 RSS 不是 BRAM 或 NPU 内存。

## 证据与回归

原始运行分开保留在 `../runs/mvsplat_fast_pair_board_v1`、`../runs/mvsplat_fast_fused_board_v2`、`../runs/mvsplat_fast_calibrated_board_v3`。每个目录有板端 pipeline_result、阶段日志/监控、相机、高斯清单、CPU/FPGA 帧缓冲以及质量报告。后两轮共 24 次 CPU/FPGA 输出均完成、下载后核对哈希；默认分阶段另有 12 次输出。ARM boot_id 为 `e2be34c6-bf58-4cea-a424-06a3f38893b9`。

失败的首个融合版本保留：OpenCV 先加载导致 Torch 的 libgomp TLS 导入失败，未渲染；修正为先导入 Torch 后完成 v2。最后将固定目标索引改为按视频长度选择：8 项本地接口测试通过，板端重新准备同一视频的 context.npz SHA256 与 v2 完全相同。该回归不是新增一次端到端性能样本。

效果图和精简指标的可提交副本见 `results/20260929/`；原始大文件仍在被忽略的 runs 中。`evaluate_fast.py` 用于快速核验，完整协方差独立参考仍使用 `reference.py/evaluate.py`。

## 当前判断与后续顺序

板端视频到高斯再到 FPGA 图像的功能链已经完成。快速候选接近一分钟，但一分钟延迟与三视角质量同时合格尚未达到；完整质量基线继续可回退。优先补相机内参、关键帧共同视野检查和有限几何优化，再测质量与首图，避免依靠错误几何抢时间。之后减少网络与渲染重复启动，建立常驻多相机渲染/模型复用入口；再评估 NPU 承担网络大块计算的端到端收益。多组对齐/融合与完整视频覆盖单独验证，不把当前两视图局部重建宣称全场景完成。
