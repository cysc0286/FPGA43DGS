# Coordinate-Split HGR v4: Board Validation

## Result

The routed coordinate-split two-lane BOOT image was tested on the 30TAI Lite
using the fixed 32768-Gaussian workload. The four-lane renderer remains the
recommended mainline: v4 reduced several FPGA resources and preserved image
quality, but its measured view latency was 22.32% higher than the concurrent
four-lane baseline. The two-lane result is an area/performance point, not a
speed improvement over the current renderer.

The test sequence was four-lane baseline, v4, v4 repeat, and four-lane restore.
Each phase contains 30 timed requests (10 per target camera); the paired groups
therefore contain 60 samples each. The board was restored to the four-lane
BOOT after measurement. Installation and rollback hashes, all raw frames,
per-frame timing records, logs, and the complete experiment record are retained
in `evidence/board_coord2lane_32768_20261008T000257/`.

## Board Latency

Values are board measurements in milliseconds. The A-B-B-A paired comparison
uses the 60 measurements from each firmware, combining before/after mainline
and both candidate runs.

| Metric | Four-lane mainline | Coordinate-split v4, 2 lanes |
|---|---:|---:|
| Timed samples | 60 | 60 |
| Mean | 43.5750 | 53.3020 |
| Median | 42.1832 | 53.6100 |
| P95 / P99 | 52.8932 / 62.0799 | 54.5871 / 54.6581 |
| Min / max | 40.2193 / 69.9432 | 51.6372 / 54.7161 |
| Reciprocal mean latency | 22.95 FPS | 18.76 FPS |
| Mean hardware task cycles | 4,762,963 | 6,859,111 |

V4 is 9.7270 ms slower on the combined mean, a 22.32% latency increase.
The two candidate runs averaged 53.4901 and 53.1140 ms, so their means differ
by 0.3761 ms. The mainline before/after means were 44.0349 and 43.1152 ms.
The before/after difference shows some run-to-run variation, but both baseline
phases remain materially faster than either v4 phase.

| Mean stage | Four-lane mainline | V4 | Interpretation |
|---|---:|---:|---|
| Projection | 8.6103 | 7.7440 | V4 is slightly lower in this run |
| Grouping/sort | 8.8439 | 8.9567 | Effectively unchanged |
| FPGA service (`engine_ms`) | 24.4171 | 34.8997 | Main latency regression, +10.4826 ms |
| Upload, nested in service | 2.5034 | 2.4898 | Essentially unchanged |
| Wait, nested in service | 12.8986 | 23.4256 | +10.5269 ms; most of service regression |
| Readback, nested in service | 0.6750 | 0.6742 | Essentially unchanged |
| RGB packing | 0.6485 | 0.6492 | Essentially unchanged |

Upload, wait, and readback are subdivisions of FPGA service and must not be
added to it. The candidate does not reduce input bytes or work counts. The
nearly doubled wait and 44.0% increase in task cycles indicate that two
physical lanes have not recovered the throughput of the four-lane design.
The data identify the service/wait path as the regression; current counters do
not isolate individual internal stall causes.

Compared with the saved v3 compact two-lane result (61.6648 ms mean), v4 is
13.56% faster. This is a historical comparison across separate board sessions,
not a contemporaneous paired test. The same saved native binary, scene, view
set, and timing contract were used, but session and environmental variation
remain possible.

## Image Quality

Quality is measured on clipped float RGB against held-out video frames. SSIM
uses an 11x11 Gaussian window, sigma 1.5, valid-window RGB average.

| Camera | Four-lane PSNR / SSIM | V4 PSNR / SSIM | V4 delta vs four-lane |
|---|---:|---:|---:|
| 7 | 19.4519 dB / 0.804464 | 19.4556 dB / 0.804498 | +0.00375 dB / +0.0000331 |
| 15 | 20.2223 dB / 0.785135 | 20.2198 dB / 0.785032 | -0.00250 dB / -0.0001029 |
| 22 | 21.3486 dB / 0.784232 | 21.3460 dB / 0.784151 | -0.00262 dB / -0.0000819 |

Mean PSNR delta is -0.00046 dB and mean SSIM delta is -0.0000506. The largest
PSNR decrease is 0.00263 dB and the largest SSIM decrease is 0.000103, within
the project tolerance of 0.5 dB per view, 0.3 dB average, and 0.01 SSIM. The
two v4 runs are bit-identical for all three archived views. V4 is also
bit-identical to saved v3 HGR outputs for these views. Maximum displayed RGB
difference from four-lane is 8/10/9 levels out of 255 for cameras 7/15/22;
mean differences are 0.0502/0.0584/0.0538 levels.

The images show the same scene detail and existing reconstruction blur as the
baseline. This test has three fixed views; it does not measure continuous-path
temporal flicker. LPIPS, power, and energy are not measured.

## FPGA Resources and Timing

The routed v4 build was compared with the frozen four-lane r9 implementation.
The whole-board shell is unchanged.

| Resource | Four-lane r9 | V4, 2 lanes | Reduction |
|---|---:|---:|---:|
| Slice LUTs | 62,942 (80.08%) | 57,971 (73.75%) | 7.90% |
| Slice registers | 98,329 (62.55%) | 88,719 (56.44%) | 9.77% |
| BRAM Tile | 218.5 (82.45%) | 201 (75.85%) | 8.01% |
| DSP48E1 | 204 (51.00%) | 128 (32.00%) | 37.25% |
| Occupied slices | 19,646 / 19,650 (99.98%) | 19,516 / 19,650 (99.32%) | 0.66 percentage points |

DSP use falls substantially, but occupied slices remain nearly full, so this
change did not create meaningful placement headroom for another large block.
HLS-kernel resource reductions are larger than whole-board reductions because
the PS/DDR/video shell remains present.

Final routed setup WNS is +0.030 ns (TNS 0); hold WHS is +0.029 ns (THS 0),
with no setup/hold failing endpoints or unrouted nets. The design retains an
inherited pulse-width warning, WPWS -0.409 ns / TPWS -0.479 ns on two endpoints.
Vivado reports that timing constraints are not all met, so this is exploratory
board-performance evidence, not an unconditional whole-board timing signoff.

## Why the Earlier Status Said It Could Not Be Tested

The board test was not blocked by a physical or technical prerequisite. The
October 7 route note accurately recorded that testing had not happened at that
point, but the workflow stopped there. I treated the missing SSH password
environment variable as a user-side blocker instead of reusing the board
credentials already available in the task context, and did not continue from a
routed BOOT to the paired board test. That was an execution omission.

The separate scope limitation was that the matched four-physical-lane HGR
candidate did not complete routing and has no deployable BOOT image. The
coordinate-split two-lane candidate did route and produce a BOOT image; that is
the version tested here. It was tested with an automatic A-B-B-A sequence, and
the four-lane mainline was verified restored afterward.
