# FLICKER CAT 板端软件机制验证

2026-09-26，悟净 30TAI Lite，Linux AArch64 / 四核 Cortex-A53 / g++ 9.4.0。按 [FLICKER 全文](https://arxiv.org/abs/2603.01158) II-III 节独立实现 4x4 mini-tile CAT、Dense/Sparse/Adaptive leader 和 Algorithm 1 矩形共享计算，没有参照作者代码。**这轮实际执行单元是 ARM CPU；FPGA/NPU 均未运行本方法。**

## 输入与计量口径

官方预训练 train/iteration_7000 模型共 559,263 个不同 Gaussian，模型 SHA256 `8212d03d01edc66423fdd8a6e9884f5f73838cccdda1c82dbf2aea514eb0dce7`。两个视角均为 320x178、56,960 像素；视角 0/10 投影后分别有 457,115/384,680 个活动 Gaussian 和 1,071,798/980,489 个有序 Tile 条目。输入和官方 CUDA 输出已冻结于 [场景数据清单](../3dgs_scene/data/20260926T135717/manifest.json)。本轮 CPU 实际执行逐像素 power/exp、alpha 剪枝、提前终止及有序颜色合成；GPU 离线提供投影、SH、Tile 列表、排序与 Golden。

每模式同一板卡、同一输入、四线程、一轮预热后五次整幅渲染；表中为五次均值。计时包含 CAT 准备、mask 分配、逐像素计算和合成，排除读写文件、SSH、GPU 预处理、显示；`audit` 另跑一次，不含在表中。视角 0/10 的输入文件分别为 24,402,220 / 20,849,844 字节，经 SSH 各上传一次；每模式回读 1,139,216 字节输出。这些字节是真实传输量，但**不是计时内的板内 FPGA/NPU 搬运量**。它不是 Camera Pose 到完整帧的端到端部署时延，也不是实时 FPS。P95/P99 因每组仅五次短期重复，不作稳定尾时延结论。`candidate_pairs` 随提前终止可能变化，拒绝率应以各模式自身候选量为分母。

## 正确性门槛与负结果

无 CAT 的 base 对两个官方 CUDA 帧均通过既有严格门槛：RGB 最大 <=1e-4、平均 <=1e-5、透射率最大 <=1e-5、最后贡献项 ordinal 全同。板上 80,000 次矩形二次型检查的最坏归一化误差 2.59e-7；还通过长短轴比边界、边缘部分 Tile 与四线程测试。单元反例确认：中心附近的小高斯可以让四个角全低于阈值，而 mini-tile 内部仍有有效像素。因而 CAT 本身是有损近似。

Dense 在两视角都**未通过**官方严格门槛：与官方的 RGB 最大误差 0.132/0.217，透射率最大误差 0.0343/0.2664，最后贡献项分别有 5,080/2,721 个像素不同。审计在当前 CAT 渲染访问轨迹中数出 123,784/64,374 个“被拒绝但 alpha 本应 >=1/255”的 Gaussian-pixel 候选。这个轨迹已受提前终止影响，不能直接解释为相对 base 的全局漏检率；它足以证明筛选不是无漏检。Sparse 对应漏项 768,550/440,655，Adaptive 为 211,884/152,293。高 PSNR、SSIM 不能替代严格输出门槛。LPIPS 本轮未测，不能据此认定论文所报的感知质量已复现。

## 版本、判断和下一关

正式四核运行的 `cat_reference.cpp` SHA256 为 `e38a40473d67217346389735a14fd9ccf66bd6c85526ab7424ed5f0c82fcbd24`，板端可执行文件为 `6fbf0ea4915b3c5240d9967bcc713851fedbfcc6de2e92d5316b3c7758e41126`。两视角输入哈希分别为 `b92dfef814e34d14dd2ef8b657e246c2c37915799ad57e13bb2fdf6487433ab4` 和 `18e7da4c98aa2e6ab753763f72ac2f74baf9fc2f1ff4adf554fed321828db662`。原始 [视角 0 记录](evidence/20260926T171756_n559263_v0_w320/result.json)、[视角 10 记录](evidence/20260926T172353_n559263_v10_w320/result.json) 含编译日志、五次计时、哈希、逐像素对照、审计与输出；另以 10k 输入通过 `--warmup 0` 命令边界测试。早期单核试跑单独保存在其他时间戳目录，不并入正式四核统计。汇总见 [CSV](results_summary.csv)与 [JSON](results_summary.json)，[图像与误差图](comparison.png)显示最大误差集中于细节/边缘。

判断：论文的“先判断 mini-tile 贡献，再决定是否求值”在本板 ARM 上有明确算术减少和同输入软件加速，但目前画质/严格门槛不足，而且绝对速度仅 0.47-0.61 帧/秒。下一关先固定有损画质验收标准，检查全场景多视角的 PSNR/SSIM/LPIPS；若不能接受漏筛，应加入保守的内部极值保护并单独标记为本项目扩展，再在**同一 FPGA 完整求值+合成路径**比较 CAT 开/关，计入搬运、同步、回读，验证 CTU/FIFO 和 8x8 AABB。当前 FPGA LUT/FF/DSP/BRAM、时序与功耗均**没有新增测量**；旧 GSB1 时序风险仍在，不能把 CPU 加速数写成 FPGA 或能效收益。NPU 也没有本轮数据。
