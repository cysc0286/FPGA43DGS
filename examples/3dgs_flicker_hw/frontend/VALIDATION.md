# CPU 前处理、排序与 FPGA 渲染闭环

更新：2026-09-28。当前基础渲染链已从官方训练模型 PLY 和相机参数在开发板上完成，运行时不再依赖 GPU 导出的投影或有序列表。训练仍在部署前完成，本轮不涉及 NPU、摄像头、位姿估计或下游任务。使用同一官方 train/iteration_7000 模型，559,263 个高斯，v0/v10 两个固定视角，320×178，每视角 240 个 Tile。

CPU 负责 PLY 读取、投影/协方差/SH、可见性和 Tile 范围、深度排序、参数打包及 SDK 双缓冲搬运。FPGA 负责 8×8 sub-tile AABB、4×4 Mini-Tile CAT、像素求值、alpha 筛选、提前终止和有序合成。算法仍需深度排序。

## 验证结论

1. 属性模块：457,115 / 384,680 个有效 Gaussian 的 ID 与官方导出一致，遗漏为 0。全部字段误差见 [属性校验](../evidence/frontend_attr_20260927T231255/validation.json)。
2. 分组排序：四种 CPU 实现对两个完整视角生成的场景文件逐字节一致。选用连续 64 位深度/ID 键排序，单次排序核 86.946 / 73.265 ms，原逐 Tile 稳定排序为 1143.844 / 996.895 ms。这里只是单次机制比较，不能作为稳定分布结论；文件读写时间另列。
3. 与官方 GPU 列表相比：v0 成员完全一致，v10 少 4 个 Tile 实例，没有多余实例或重复项，活动高斯本身没有遗漏；73 / 56 个 Tile 的列表次序或成员不同。CPU/GPU 属性数值差异已记录，不宣称列表逐位等价。见 [列表校验](../evidence/frontend_group_20260927T233920/validation.json)。
4. 新列表的 FPGA 原始输出：两视角各 983,040 字节，均与对应的 HLS FP16 Golden 零差异；计时实验的最终 framebuffer 也逐字节一致。见 [v0](../evidence/frontend_hls_v0_20260927/timed_frame_check.json)、[v10](../evidence/frontend_hls_v10_20260927/timed_frame_check.json)。
5. 正式整链对照：预热 1 次、计时 3 次，三条后端各自重复输出无漂移；同组 CPU/FPGA 使用完全相同的板端场景输入。质量门槛通过，官方 FP32 严格门槛失败，两者分别保留。

## 整链耗时与画质

计时从读取 PLY 开始，到一次渲染并写完 framebuffer；包含 CPU 属性/分组/排序、进程启动、SDK 初始化、文件与内存操作、FPGA 数据搬运和回读。中间数据在 tmpfs，PLY 读取可能命中 Linux 缓存，不是冷启动 SD 性能；不含 SSH 下载、显示刷新或训练。

板端日历时钟尚不准确（SDK日志显示3月13日）；证据目录使用主机日期，性能计时使用单调时钟，不受这项日期偏差影响。进程超时监控的等待也包含在外部墙钟中，不能等同于常驻程序的紧凑计算时延。

## 与 FLICKER 的对应及后续边界

本轮完成了基础 3DGS 部署所需的前处理、排序、筛选和渲染功能链；**没有完成整篇 FLICKER 的全部机制复现**。论文依据为本仓库冻结全文 [§IV–V](../../../papers/metadata/06_FLICKER_DATE2026.txt)。

|论文环节|当前部署|状态与差别|
|---|---|---|
|投影、协方差、SH、可见性|板端 ARM CPU|已运行；仍逐 Gaussian 读取，静态协方差每次重算|
|深度排序|板端 ARM CPU|已运行；排序后分发 Tile，未采用论文硬件排序单元|
|sub-tile AABB、Mini-Tile CAT、PR 共享|FPGA|已运行；AABB 位于排序和参数传输之后，未节省这部分输入流量|
|FIFO、背压、VRU 有序渲染|FPGA|已仿真和实板；按资源缩小为四 VRU，非论文并行数量|
|主机供数与执行重叠|CPU＋SDK＋FPGA|实板串行/流水对照有收益；未实现跨帧常驻流水|
|FP16 相对坐标＋FP8 CTU|尚无|当前 CTU/VRU 使用已有 FP16 契约|
|大 Gaussian 聚类、按通过测试结果选择读取 SH|尚无|当前未复现论文的内存访问优化|
|30K 训练、剪枝、3K 微调|尚无|当前为官方 7K 模型，不能套用论文 FPS 或画质表|

当前的优势是 FPGA 调度收益已在不改变数值的条件下成立，且整链确实能比四核 CPU Dense 更快。限制是两视角、低分辨率、重复初始化和单线程 CPU 前处理；整板 Slice 几乎满载。前处理占整链约 67%，即使把渲染进程降到零，当前前端仍约 2 秒。下一步优先常驻模型/静态协方差和连续缓冲、CPU 前处理并行，再按论文补聚类与选择读取；更多功能下沉 FPGA 前须先解决布局空间。仅缩短上传的约 64–70 ms 不能解决秒级总耗时。
