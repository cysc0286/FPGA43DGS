# FLICKER FPGA v0 接口合同（开发中）

采用论文的全 FP16 渲染分支建立初始硬件基线，后续混合精度 CTU 单独开启。半精度与严格 FP32 官方图像分开比较，不改原官方严格门槛，不将近似通过写成严格通过。

输入是连续 64 字节记录：每个 Tile 一个头，随后 N 个按深度排序的 Gaussian。每条 Gaussian 一次传输，在 FPGA 内复用于最多 256 个像素。当前版本保留 Tile 间重复属性，后续聚类/缓存消融不得与当前版混算。

头字段（bit，little endian）：N[31:0]；origin_x[47:32]；origin_y[63:48]；有效宽[68:64]；有效高[73:69]；背景 R/G/B binary16[95:80]/[111:96]/[127:112]。尺寸各为 1..16。其余为 0。

Gaussian 字段：连续 9 个 binary16，顺序 mean_x, mean_y, conic_a, conic_b, conic_c, opacity, R, G, B。当前模式为 0；非零拒绝，不悄悄忽略。

输出每像素 128 bit：R/G/B/T 各 16 bit，最后贡献的 Tile 列表序号（从 1 起，空为 0）32 bit，像素 tag=本批 tile_index*256+pixel_index 32 bit。4 像素打包成 512 bit，每个 Tile 恰好 64 条输出。边缘无效像素不参与图像验收。

半精度计算逐运算舍入，指数使用 HLS `half_exp`；不再使用旧 Q16 粗查表。alpha clamp=.99，最低 alpha=1/255，先判断 next_T<1e-4，再决定是否累加；终止后保持颜色/T/last。需要实测 HLS 半精度数值相对原 FP32 的质量，不能从格式推断通过。

DDR 地址为 SDK 分配的设备地址，64 字节对齐；不等于 CPU 指针。由 SDK 成块写入和回读。新 DMA 精确读取声明条数，预取队列具有背压，最后输出写握手后对末地址做读屏障，之后才能报告完成。复用存储前必须收取对应任务完成信息。

性能统一报告准备、SDK 块写、提交、等待、SDK 回读、总时间；硬件周期是等待时间内部，不重复相加。预取/执行重叠与 CPU 上传下一批的重叠分别验证。新位流未经验收不得覆盖当前 GSB1。

计数器 0x244 统计 `kernel_read && !kernel_empty_n`，即无法服务的读取请求。HLS 的 FIFO 读取使能在空时会撤销，因此这个值不能测出全部饥饿/等待周期，CSV 命名 `unserved_kernel_read_requests`；RTL 历史端口名 `input_starve_cycles` 不作为其物理解释。真正的内核等待分解还没有独立观测点，不能将 0 写成“无等待”。0x240 统计收到预取响应、内核已经消费输入且尚未完成、该拍未取新输入的周期。
