# 项目要求

更新：2026-11-04，用户明确要求按原五部分加网页共六部分整理，并删除主线无关代码。

1. 业务代码只归 `mvsplat/{initialize,video_input,pose_estimation,gaussian_generation,rendering,web}`。实现、测试、编译和模块说明随归属放置；跨模块工具／说明使用根 `tools`、`docs`。
2. `initialize` 管理预热和已有阶段的调用，不重写几何或网络。HTTP、页面和浏览器交互归 `web`；图像接收、相机数学、推理和渲染仍归各自模块。
3. 保留采纳的四局部子图加六 FFN、CPU 显式回退、当前位姿和生成数据语义。不能把部分 NPU 描述为全网 NPU，不能将错误或陈旧输出计为加速。
4. READY 前继续核验输入切换、有限值、重复性和实际资产／源码身份。严格 TF32 失败事实不改写；新目录或代码需要对应的新资格。NPU 失败不得静默改跑 CPU。
5. 渲染继续使用四路冻结 `render_main` 和匹配 BOOT；不因结构整理改 RTL／硬件。共享设备的打开顺序、64 MiB 设备地址隔离、700 MiB PSS／96 MiB 系统余量保护保留。
6. 预热和视频输入只记录。场景准备计时从 VIDEO_COMPLETE 到首帧 FRAME_COMPLETE；换视角和网页就绪另报。无上板操作就不得声称新板端时间、画质或资源结果。
7. 删除前在仓库外校验备份。只清当前 checkout 的无关文件，不动其他工作树、运行板卡、私人录像或未知生成结果。私有素材、令牌、账号、权重和 SDK 不提交。
8. 仅同协议合格结果可比较；按原保优规则回收非优生成物时先保存指标／哈希／原因摘要。运行中、显示中和无标记目录不删除。

当前目录与交接见 [CODE_STRUCTURE.md](CODE_STRUCTURE.md)，实板状态见 [MAINLINE.md](../MAINLINE.md)。
