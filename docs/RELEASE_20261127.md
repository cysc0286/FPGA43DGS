# 相机与覆盖修正主线汇总

日期：2026-11-27。以 GitHub `main` 的 `14a8379942d64a59abbe90dd6c4eae34670105f0` 为基础，合入本地工作版本增量。沿用根目录 README／MAINLINE 和六部分模块格式，不移动已有文件，不用旧快照覆盖主分支画质、第三方源码或固件资产。

## 内容

- `video_input`／`web`：手动 UVC 曝光、增益、亮度；按实测帧率接收，严格检查改为显式选项。
- 密集慢转跨帧配对和准备后缓冲释放通过 `coverage` 选项合入，原 `balanced`／`legacy` 保留。
- 网页默认对应当前部署：CPU＋FPGA、15 秒、最多 2 对、至少 1 对、64 候选、65536 点预算、关闭低频外观修正。NPU 需显式配置，不静默启用。
- 云台完整脉冲停止、jog、平台隔离构建、ROM 路径检查及 ABI3 本机记录保留在原模块。当前不自动驱动电机，不刷写板卡。
- 旧 ABI2 固件和报告保持原字节，匹配 PWM 源码在同目录存为 `camera_servo_pwm_abi2.v` 并调整清单引用，避免把活动 ABI3 RTL 当作该旧镜像的构建输入。

主分支已有 MVSplat 快照、外观修正、融合／采样和均衡视角策略继续保留。私有录像、标定样本、生成场景、令牌、SSH 环境及重复实验部署快照不提交。原工作分支及逐文件哈希备份保留，发布不修改开发板服务。

## 部署与验证边界

当前硬件分工、运行入口及历史指标见 [README](../README.md)、[MAINLINE](../MAINLINE.md)。权重、SDK、NPU 图包和资格记录需另行配置。标准部署器包含包入口和采集／上传静态资源；不能仅复制部分文件后静默回退旧版。

本轮仅做本机合并回归、打包及冻结资产检查；11 月 21 日延迟、覆盖、画质和内存数据为历史记录。NPU 接入已停止，没有新 NPU 成绩；深度不可观测、中心裁剪、画质和多对内存限制保留。功耗、DDR／DMA 流量、硬件利用率本轮未测。

优点是合入当前采集和覆盖修正，同时保留主分支已有策略、画质流程和资产；代价是增加一种显式配对策略与两份 ABI 的源码区分。测试支持本机接口和发布完整性，不支持新加速或节能结论。当前主要限制仍是 ARM 生成耗时、内存余量和纯旋转深度不可观测。

复现时，在仓库根目录运行 `python tools/check_core.py`、`python tools/check_render_packages.py`、`python tools/check_camera_firmware.py`；完整依赖就绪后可运行 `python tools/check_core.py --mvsplat`。在 `examples/3dgs_reconstruction/mvsplat` 下运行 `python -m unittest initialize.test_structure video_input.test_ring_coverage video_input.test_ring_balance video_input.test_camera_controls video_input.test_capture_fps web.test_camera_resident` 核对关键入口。

本地原始日志和逐文件备份位于仓库外 `tmp/github_publish_20261127/`，不随发布上传；其中 `final_regression.json`／`.log` 是最终可运行回归记录，早期失败的探索日志另存。
